## §1 标的识别与代码输入（S1）

### 1.1 现状问题

系统现有 `GET /api/symbols/search` 已支持裸 6 位代码 / 带前缀 / 中文名模糊匹配，
前端输入框也已有下拉与键盘导航。**但存在两个真实缺口：**

| 缺口 | 现象 |
|---|---|
| **提交时未自动补前缀** | 用户输入 `600000` 后若不选下拉直接提交，`asset_code` 校验失败（要求 `sh`/`sz` 前缀）→ 400 |
| **联想结果不含名称** | 现有接口已返回 `name`，但需在所有录入入口统一展示（§1.3） |

### 1.2 不变量

| 编号 | 不变量 |
|---|---|
| **INV-S1-1** | 用户**不需要知道交易所前缀**。系统接受裸 6 位代码并自动解析为完整 `asset_code` |
| **INV-S1-2** | 解析结果**唯一**。若裸代码在系统标的字典中命中多条，不得静默取第一条，必须让用户选择 |
| **INV-S1-3** | 联想列表**必须同时展示标的代码与标的名称** |
| **INV-S1-4** | 联想**必须支持按名称搜索**（中文全称 / 简称 / 拼音首字母） |
| **INV-S1-5** | 联想结果**不得包含**已退市 / 无行情的标的（除非用户显式按代码精确匹配） |
| **INV-S1-6** | 联想失败**不阻断输入**：用户仍可手工输入完整 `sh600000` 形式的代码 |
| **INV-S1-7** | 联想输入**不得触发行情层全表扫描**（性能约束，见 §10） |

### 1.3 覆盖的输入入口

以下入口**必须共用同一套联想组件与解析规则**，不得各写一套：

- 交易录入（买入 / 卖出 / 加仓 / 减仓 / 清仓）
- 复盘筛选
- 候选池添加
- 自选股添加
- 持仓查询筛选

### 1.4 标的名称的来源

标的名称**只从行情层读取**（`raw_symbol_name`），不作为用户可编辑字段。
若名称在行情层缺失，联想结果**展示代码 + 空名称**，不报错、不阻塞。

## §2 券商流水导入与对账（S2）

### 2.1 业务目标

用户的核心诉求**不是「省去手工录入」，而是「让系统算出的持仓与盈亏能被券商流水验证」**。

因此导入功能的**首要产出是一份对账报告**，补录是其次。

### 2.2 数据来源分类：文件之间是「子集 + 增量」关系

导入器必须按**文件能力**而非「券商名称」分类。**实测证明同一券商的「成交流水」与
「交割单」不是并列的两个数据源，而是子集关系：**

```
交割单  =  成交流水  ∪  非成交事件（分红 / 份额折算 / 申赎杂项 / 特殊调账）
           ↑ 有成交时间      ↑ 无成交时间
```

| 券商 | 成交流水 | 交割单 | 实测 |
|---|---|---|---|
| 甲 | 有成交时间（百分秒） | **无**成交时间，仅交收日期 | 成交 125 行全部匹配到交割行；交割独有 9 行**全是非成交事件**（货币ETF申赎杂项 4、基金现金分红 5） |
| 甲（股票） | 有成交时间 | 无成交时间 | 成交 12 行全匹配；交割独有 2 行 = 红利入账 |
| 乙 | 有成交时间 | **也有**成交时间 | 两文件内容重叠，跨文件去重后取信息更全的交割单 |

**文件能力分类**：

| 能力 | 关键差异 |
|---|---|
| **A 类：含成交时间** | 成交时间精确到秒或百分秒 → 匹配可到秒级 |
| **B 类：无成交时间，仅交收日期** | → 匹配只能到日级；**同日多笔必须按出现顺序配对** |

**正确处理方式（实测得出）**：**以交割单为记录骨架，用成交流水回填成交时间**，
而不是把两者当两个独立数据源各自匹配。详见 §2.9.5。

### 2.3 解析不变量

| 编号 | 不变量 |
|---|---|
| **INV-S2-1** | 解析器**按表头特征识别文件类型与列含义**，不依赖用户选择券商。识别依据须为**表头列名组合**（如「同时存在余额类列与方向类列」→ 交割单类型） |
| **INV-S2-2** | 解析器**必须向下扫描定位表头行**。不得假设表头在首行 |
| **INV-S2-3** | 解析器**必须处理非 UTF-8 编码**（中文 CSV 常见 GBK / GB18030）。编码嗅探顺序与失败提示见 §10 |
| **INV-S2-52** | 解析器**不得硬编码列名**。实测同一份交割单内，语义相同的两个字段用了**不同的字**（「资金发生**数**」与「资金余**额**」）。列名匹配必须容忍同义 / 错字，或以「列位置 + 数值自洽性」双重确认 |
| **INV-S2-53** | 解析器**必须兼容多种单元格包裹风格**。实测同一券商的不同导出入口分别使用 `="值"`、`"值"` 与原生值三种形式 |
| **INV-S2-4** | 解析器**必须支持伪 Excel 文件**（扩展名为 `.xls`/`.xlsx` 但实为制表符分隔文本） |
| **INV-S2-5** | 解析器**必须识别并排除废单**（无效申报：成交编号非数字形态且金额与数量均为 0） |
| **INV-S2-6** | 解析器**必须保留每一行的原始内容**，不得只存规范化结果。规范化缺陷可据原始内容重放修复，无需用户重新上传 |
| **INV-S2-7** | 解析器**遇到未知交易类别不得丢弃该行**，须保留并标记为「待映射」，在报告中列出 |
| **INV-S2-8** | 文件中的**敏感字段（资金账号、股东代码、营业部名称、用户名）一律丢弃**，不落库、不入日志 |
| **INV-S2-9** | 同一文件重复上传**不得产生重复记录**（幂等，见 §2.9） |
| **INV-S2-10** | 导入**不得直接写入系统记录**。必须先落券商原始记录层，经用户确认后才可补录（§2.8） |

### 2.4 规范化事件类型

跨券商的原始方向表述**共 37 种以上**（实测两个券商合计），必须归一到统一枚举。

| 事件类型 | 含义 | ① 进系统记录<br>（作为交易） | ② 进事实层<br>（可对账/可归因） | ③ 参与收益计算 |
|---|---|---|---|---|
| `TRADE_BUY` | 买入（竞价/盘后/大宗） | ✅ | ✅ | ✅ |
| `TRADE_SELL` | 卖出 | ✅ | ✅ | ✅ |
| `FUND_SUBSCRIBE` | **场内**基金申购（场内 LOF / ETF 申购确认） | ✅ | ✅ | ✅ |
| `EXCLUDED_OFFEXCHANGE` | **场外**基金申购 / 赎回 | ❌ | ✅（保留并归因） | ❌ |
| `FUND_REDEEM` | 场内基金赎回 | ✅ | ✅ | ✅ |
| `DIVIDEND_CASH` | 现金分红 / 红利入账 | ✅ | ✅ | ✅ |
| `DIVIDEND_BONUS` | 送股 / 份额折算 | ✅ | ✅ | ✅ |
| `TRANSFER_IN` | 转托管转入 / 调帐转入 | ✅ | ✅ | ✅ |
| `MARGIN_SHORT` | 信用融券卖出 | ✅ | ✅ | ✅ |
| `MARGIN_REPAY` | 融券购回 | ✅ | ✅ | ✅ |
| **`REPO`** | **国债逆回购**（普通账户下券商记为「融券 / 融券购回」） | ✅ **作为现金类资产**（§3.5） | ✅ | ✅ **利息计入** |
| **`CASH_LIKE_ETF`** | **货币 ETF 申购 / 赎回 / 场内买卖** | ✅ **作为现金类资产**（§3.5） | ✅ | ✅ **市值变动计入** |
| `PLACEHOLDER` | 指定登记等占位事件 | ❌ | ✅（保留并归因） | ❌ |
| `IGNORE` | 资金划转、利息入账等非交易事件 | ❌ | ✅（保留并归因） | ❌ |
| `UNKNOWN` | 未识别 | 保留待映射 | ✅ | ⚠️ 报告列出 |

#### 2.4.2 归一化规则

| 编号 | 不变量 |
|---|---|
| **INV-S2-11** | 原始方向表述**必须归一到 §2.4.1 枚举**，映射表**以数据形式维护**（非代码分支），因为券商会新增品种表述 |
| **INV-S2-12** | 归一化**必须保留原始表述**（可追溯） |

#### 2.4.3 记录来源类型

事实层可容纳**两类来源**，共用同一套导入管线与对账引擎：

| 来源类型 | 含义 | 是否进系统记录 |
|---|---|---|
| `broker` | 券商导出的成交流水 / 交割单 | 可（经用户确认后补录） |
| `manual_sheet` | **用户自有的交易记录表**（如手工维护的投研记录） | **不进**（owner 决定），仅作对账的**第三方参照** |

> 引入 `manual_sheet` 的理由：用户自有的手工记录**独立于系统与券商**，是天然的第三方基准。
> 把它接进事实层（而非业务记录层），可对「券商 ⟷ 系统」的主对账做**交叉验证**：
>
> | 券商 | 系统 | 用户自有表 | 判读 |
> |---|---|---|---|
> | 一致 | 一致 | 一致 | 高置信度 |
> | 一致 | 一致 | **不一致** | 用户自有表漏记或错记 |
> | 一致 | **不一致** | 一致 | 券商流水未导全 |
> | **不一致** | 一致 | 一致 | 券商流水与用户记录口径不同，需人工判读 |
>
> 该能力**不要求用户自有表进入业务记录**，因此不改变「历史数据不进系统」的边界。

| 编号 | 不变量 |
|---|---|
| **INV-S2-43** | 事实层必须记录**来源类型**，且来源类型不得由文件名或券商推断 |
| **INV-S2-44** | `manual_sheet` 来源**不得被补录进系统记录**。它只参与对账与交叉验证 |
| **INV-S2-45** | 三方对账**必须分别呈现**三方各自的一致 / 不一致，**不得合并成单一结论** |
| **INV-S2-46** | 用户自有表的**覆盖区间必须单独声明**。它常与券商流水区间不同（实测手工记录早 4 个月），区间外不构成「已核对」 |
| **INV-S2-47** | 交叉验证**只读**，不得因交叉验证结果而修改任何一层记录 |

### 2.5 字段归一化

| 编号 | 不变量 |
|---|---|
| **INV-S2-14** | 证券代码归一为 `<市场前缀><6 位代码>`。原始代码长度**不固定**（实测出现 3/4/6 位），补零规则见 §10 |
| **INV-S2-15** | 原始单元格**可能带前导制表符 / 空格**，解析时必须去除 |
| **INV-S2-16** | 日期归一为 `YYYY-MM-DD`；时间归一为 `HH:mm:ss`（**丢弃毫秒**）。无时间的文件保持为空。**成交日与交收日必须作为两个不同语义分别保留**，不得混用（§2.9.5 的匹配优先级依此设计） |
| **INV-S2-17** | 价格 / 数量 / 金额归一为数值。原始文件常以**定长小数字符串**存储（`111.000` / `100.0000`），须正确转换 |
| **INV-S2-18** | **发生金额 / 资金发生额**（买入为负、卖出为正）若存在，**必须保留**。它是现金流校验的唯一依据（§2.9.3） |
| **INV-S2-19** | **成交后证券余额**、**成交后资金余额**若存在，必须保留。前者是推导交易类型的原料（§3.2） |
| **INV-S2-20** | 费用明细若存在，**必须保留分项**（实测某券商有 10 个费用分项），不得只存合计 |

### 2.6 对账规则

#### 2.6.1 匹配分级

按**文件能力**选择匹配键：

| 级别 | 适用 | 匹配键 |
|---|---|---|
| L1 | A 类（有成交时间） | 标的 + 日期 + 时间（秒级） + 方向 + 价格(±0.001) + 数量(±0.001) |
| L2 | A 类 | L1 放宽：时间 ±2 秒（源为百分秒，源秒级截断导致） |
| L3 | A 类 | 时间一致，价格 ±0.02 |
| L4 | **B 类（无成交时间）** | 标的 + 日期 + 方向 + 价格(±0.01) + 数量(±0.001)，**同日多笔按出现顺序配对** |
| L5 | 全部 | 人工判定：系统无对应记录 → 候选补录 |

| 编号 | 不变量 |
|---|---|
| **INV-S2-21** | 匹配**必须按券商分组**。不同券商的同一标的是**互相独立的持仓**，不得跨券商配对 |
| **INV-S2-22** | 同一券商的匹配**必须覆盖该券商全部已导入流水**，而非仅当前文件 |
| **INV-S2-23** | 用户可将「系统判为缺失、但实为已手工记录」的流水**标记为已匹配**，避免重复补录 |
| **INV-S2-24** | 对账报告**必须声明覆盖区间**。系统只能看到用户导入的区间，区间外不构成「已核对」 |
| **INV-S2-25** | 差异必须**分类呈现**：完全一致 / 价格不符 / 数量不符 / 方向不符 / 缺失（券商有系统无）/ 多余（系统有券商无） |

#### 2.6.2 差异处理

| 编号 | 不变量 |
|---|---|
| **INV-S2-26** | 对账**不得自动修改**系统记录。差异只呈现，由用户决定 |
| **INV-S2-27** | 「多余（系统有券商无）」必须**保留**并单独提示 —— 这类差异往往是系统自己的 bug（如已知的交易类型映射错误） |

#### 2.6.3 差额归因

「系统与券商对不上」是**必然**的 —— 排除项、覆盖区间、口径差异都会造成差额。
系统**必须能解释差额去哪了**，而不是只报一个「不平」。

| 归因项 | 说明 | 依据 |
|---|---|---|
| 逆回购 | 在途本金 + 已实现利息 | 事实层 `REPO` 记录 |
| 货币 ETF | 市值变动 | 事实层 `CASH_LIKE_ETF` 记录 |
| 现金分红 / 送股 | 已入账但系统未体现 | §3.6 |
| 场外基金 / 占位事件 | 保留在事实层但不参与计算 | §2.4.1 |
| 未覆盖期间 | 券商流水覆盖区间之外 | §2.6.1 |
| 口径差异 | 成本口径 / 费用口径 / 收益定义不同 | §3.5.5 |
| **真实差异** | 上述都解释不了的残差 | —— |

| 编号 | 不变量 |
|---|---|
| **INV-S2-62** | 对账报告**必须给出差额归因**，把残差拆到上表的每一项。**「无法解释的残差」必须单独列出且醒目** |
| **INV-S2-63** | 归因**不得使用「其他」或「未知」作为兜底项**。无法归类的部分必须列出**具体记录** |
| **INV-S2-64** | 归因的每一项**必须可下钻到明细记录** |
| **INV-S2-65** | 报告**必须同时给出「总额口径」与「风险资产口径」**两个收益率，并说明二者差异来源（§3.5.5） |

### 2.7 按券商对账

| 编号 | 不变量 |
|---|---|
| **INV-S2-28** | 系统记录必须带**券商维度**。系统记录的券商维度**可为空**（手工录入） |
| **INV-S2-29** | 按券商对账的三个层次：**流水笔数**、**期末持仓**、**盈亏**。三者**独立呈现**，不合并成一个「对上了 / 没对上」的结论 |
| **INV-S2-30** | 盈亏差异**不得直接判定为错误**。券商成本口径（摊薄成本）与系统口径（移动加权成本）本就不同，差异必须标注口径说明 |
| **INV-S2-31** | 按券商筛选持仓、盈亏、交易列表时，**手工录入记录（无券商）必须独立成组**，不得混入任一券商 |

### 2.8 补录规则

| 编号 | 不变量 |
|---|---|
| **INV-S2-32** | 券商原始记录与系统记录**并存**，前者是不可变的事实层，后者是用户的业务记录层 |
| **INV-S2-33** | 补录**必须由用户显式确认**后执行，不得在导入时自动写入 |
| **INV-S2-34** | 补录产生的系统记录**必须可回溯到其券商原始记录** |
| **INV-S2-35** | 撤销补录**只影响系统记录层**，券商原始记录层**永不删除**（保证可重新补录） |
| **INV-S2-36** | 补录时**成交时间缺失**（B 类文件）时，系统记录的成交时间留空，**不得填充假时间**（见 §3.3 时间语义） |
| **INV-S2-37** | 补录的交易类型**必须由系统推导**（§3.2），且**必须可被用户修正** |

### 2.9 幂等与一致性

#### 2.9.1 文件级幂等
同一文件重复上传**必须被识别并拒绝或跳过**，不得产生重复记录。

#### 2.9.2 行级幂等
| 编号 | 不变量 |
|---|---|
| **INV-S2-38** | 行级幂等**不得依赖券商成交编号**。实测成交编号存在三种不可靠形态：① 电子表格科学计数法（精度已丢失）② 数字与文本混排 ③ 同一编号被两行共用（回购类） |
| **INV-S2-39** | 行级幂等键必须由**归一化内容 + 同内容出现序号**构成，使「真实存在的同内容多笔」不被误判为重复，而「同一文件重复上传」被识别为重复 |

#### 2.9.3 资金一致性校验（行内自洽）

**原设计的账户级闭合已被实测否证**，须改为**逐行自洽**。

| 实测 | 结论 |
|---|---|
| 「资金余额」列出现**百万级跳变**，而当日成交额仅几万 | 该列是**全账户总资产**，不是现金余额 |
| 同一账户的「ETF 交割单」与「股票交割单」重叠日期余额仅差 120.90 | 两文件是**同一账户的品种筛选子集** |
| 逐笔闭合 `上笔余额 − 资金发生数 = 本笔余额`：**1/134 成立** | 文件是子集 → **逐笔与账户级闭合均不可行** |
| 行内自洽 `资金发生额 = ±成交金额 ∓费用合计`：**145/148 成立**（3 行为现金分红，公式不适用） | **行内自洽是唯一可靠的资金校验** |

| 编号 | 不变量 |
|---|---|
| **INV-S2-40** | 资金校验**必须采用行内自洽**：买入 `资金发生额 = −(成交金额 + 费用合计)`，卖出 `= +(成交金额 − 费用合计)`；现金分红等无成交金额的事件，`资金发生额` 即分红额，单独处理 |
| **INV-S2-41b** | **不得做账户级 / 逐笔余额闭合校验**。实测该类校验在品种筛选文件上必然失配（1/134），会产出大量假警报 |
| **INV-S2-41** | 校验失配的行**必须归类报告**（费用口径不符 / 分红 / 口径未知），**不得笼统报「不平」** |
| **INV-S2-42** | 「资金余额」列**不得被当作现金余额使用**。实测其语义为全账户总资产，且随未导出的品种操作跳变 |
| **INV-S2-43** | 行内自洽公式**不适用的行**（现金分红、场外申赎、占位事件等无成交金额的事件）**必须单独归类**，**不得计入「不平行」统计** |
| **INV-S2-44** | 资金校验的**适用范围必须声明**：哪些文件类型参与校验、哪些不参与（无费用明细列的成交流水不参与） |

#### 2.9.4 跨文件去重（同一券商的多个导出文件内容重叠）

**实测事实**：同一家券商的「成交流水」与「交割单」是**同一批交易的不同视图**，
两者内容高度重叠（实测华宝两文件 671 行中大量行在两边同时出现）。

| 若不处理 | 后果 |
|---|---|
| 两个文件都导入 | **每笔交易被导入两次 → 持仓翻倍、盈亏翻倍** |

**判别规则**：

| 键相同（日期+时间+代码+方向） | 价与量 | 判读 |
|---|---|---|
| 同 | **同** | **同一笔交易的两份冗余导出** → 只保留一条 |
| 同 | **不同** | **真实的分笔成交** → **全部保留**，按出现顺序编号 |

> 实测对照：
> - 华宝两文件间 `20260129 13:27:11 159755 买入 价1.075 量3900` → 价量全同 → 冗余
> - 国泰交割单内 `20260420 600673 卖出` 5 行，价 33.580/33.580/33.570/33.560/33.460 → 价不同 → 真实分笔

| 编号 | 不变量 |
|---|---|
| **INV-S2-48** | 同一券商的多个导出文件**必须跨文件去重**，去重键为（标的+日期+时间+方向+价格+数量） |
| **INV-S2-49** | **同键但价或量不同**的记录**必须全部保留**，不得被当作重复折叠 |
| **INV-S2-50** | 去重**必须保留「哪些源文件提供了这条记录」**，以便报告中显示该笔被几个文件覆盖 |
| **INV-S2-51** | 冗余判定**不得依赖文件名或文件类型**（同一交易在成交流水与交割单中都出现） |

#### 2.9.5 成交时间回填（跨文件补全）

交割单缺少成交时间时，**用同一券商的成交流水回填**。

**匹配键**（实测 100% 命中，无歧义）：
```
标的 + 日期 + 方向 + 价格 + 数量
```

| 编号 | 不变量 |
|---|---|
| **INV-S2-54** | 回填**必须以交割单为骨架**（交割单含资金发生数、资金余额、费用明细、证券余额，信息更全），成交流水仅用于**补充成交时间** |
| **INV-S2-55** | 回填匹配键必须为（标的+日期+方向+价格+数量）。**不得使用标的名称**（实测同一标的存在多个名称变体，如「159530 机器人ETF易方达」与「159530 机器人E」） |
| **INV-S2-56** | 匹配键出现**多候选**时（真实存在完全相同的多笔），必须按**出现顺序**配对，并**标记为歧义**待人工确认 |
| **INV-S2-57** | **回填不得改变记录的其它字段**。回填只写成交时间，其余字段以交割单为准 |
| **INV-S2-58** | **成交流水中存在、交割单中不存在的记录，必须单独列出**。这类记录可能是成交流水的独有数据（如实为 0 行，也可能因交割单筛选条件而缺失），**不得静默丢弃** |
| **INV-S2-59** | 交割单**独有**的记录（多为非成交事件）**必须保留**，并按其事件类型归类（分红 / 份额折算 / 申赎杂项 / 特殊调账） |
| **INV-S2-60** | **日期口径必须按券商实测确认，不得假定**。实测样本中交割单的「交收日期」等于成交日（跨境ETF 同样如此），但这是**该券商该文件的实际口径**，不是通用规律 |
| **INV-S2-61b** | **日期权威源 = 成交流水的日期**（它按定义即成交日）。交割单的日期**只作辅助键**，不得作为跨文件匹配的**必要条件** |
| **INV-S2-61c** | 跨文件匹配**必须按优先级降级**：① 稳定标识（合同序号 / 成交编号）② 内容键（标的+方向+价格+数量）+ 日期窗口（默认 ±2 天，可配置）③ 内容键 + 顺序配对 |
| **INV-S2-61d** | 降级匹配**必须记录所用级别**，并在报告中单列「低置信度匹配」数量。日期窗口放宽是**最后手段**，不得作为默认 |
| **INV-S2-61** | 若某券商的交割单**本身也含成交时间**（实测乙券商如此），则**仍需跨文件去重**（§2.9.4），且信息取交割单 |

### 2.10 报告产出

对账报告必须包含：

1. 覆盖区间（起止日期 + 涉及券商）
2. 匹配统计（完全一致 / 价格不符 / 数量不符 / 方向不符 / 缺失 / 多余）
3. 资金等式校验结果
4. 待映射的未知事件类型清单
5. 被排除记录统计及**排除原因**（逆回购 / 货币 ETF / 场外基金 / 废单 / 占位）
6. **可逐条下钻的差异明细**
7. **三方对账视图**（§2.4.3）：券商 ⟷ 系统 ⟷ 用户自有表，各自的一致 / 不一致分别呈现；
   各方的**覆盖区间分别声明**（实测用户自有表早于券商流水约 4 个月）
8. **跨文件回填与覆盖统计**（§2.9.5）：每条记录标注其成交时间来自哪个文件；
   成交流水独有记录数、交割单独有记录数、歧义配对数

## §3 交易类型与成本口径

### 3.1 交易类型体系

现有 7 种（`buy`/`add`/`reduce`/`clear`/`dividend`/`bonus`/`transfer`）经实测**足以表达**
所有需进系统的券商事件 —— 无需扩展枚举，也**无需第三次表重建**。

| 券商事件 | 映射到现有枚举 | 实测依据 |
|---|---|---|
| 场内 LOF / ETF 申购确认 | `buy` | 成交价即当日净值，`数量 × 价格 = 成交金额` 恒等 |
| 现金分红 | `dividend` | `price` 语义为**每股分红**（实测 0.130 × 200 股 = 26.00） |
| 送股 | `bonus` | `quantity` = 送股数，`price` = 0 |
| 份额折算 | `bonus` | 同上 |
| 场外基金申赎 | **排除** | 见下方专条 |
| 融券 / 融券购回 | **排除**（普通账户） | 交叉表证明该词汇在本账户下指国债逆回购（§11-Q1） |

> ⚠️ 代价：`dividend` / `bonus` 的 `price` 字段**语义与成交价分叉**
> （`dividend.price` = 每股分红额，`bonus.price` = 0）。此约定必须写入字段说明。

#### 3.1.1 场外份额与场内份额的识别（高风险）

| 事实（实测） | 结论 |
|---|---|
| 行情层把场外 LOF 也标为 `class='etf'` | **不能**用 `class` 区分场外/场内 |
| 场外 LOF 在行情层**有日线数据**（实测 2314 根，最新 2026-10-12） | **不能**用「有无日线」区分场外/场内 |
| 场外申购与场内交易**代码完全相同**（同为 `sz162719`） | **不能**用代码区分 |

→ 场外与场内只能靠**流水中的交易类别**区分（实测场外记为「基金申购」，场内记为「竞价买入 / 卖出」）。

| 编号 | 不变量 |
|---|---|
| **INV-S3-1** | 交易类型集合必须能表达 §2.4.1 的全部**进系统**事件 |
| **INV-S3-2** | 交易类型的**扩展必须一次性完成**，不得分多次变更既有约束（分多次变更既有表会留下多次重建的碎片） |
| **INV-S3-3** | **买入价与卖出价不得共用一个字段**表达成对交易（现有流水模型是单边字段，需在配对视图中合并展示） |

| 编号 | 不变量 |
|---|---|
| **INV-S3-4** | 场外份额与场内份额**必须按交易类别区分**，不得按标的代码或行情层信息推断 |
| **INV-S3-5** | 场外记录**必须排除**，且在报告中单列统计与原因（**不得静默丢弃**） |
| **INV-S3-6** | 排除场外后，同一代码的场内记录**才可进入对账与补录**。若同一标的同时存在场内外记录，必须按交易类别分流，不得混算 |
| **INV-S3-7** | 场外份额若将来要支持，其**成本模型必须独立**（按申赎净值，不按行情层价格）—— 行情层提供的是场内价格，与场外净值不同源。**V3 不做** |

### 3.2 交易类型的推导规则

券商只给「买入 / 卖出」，系统需要区分建仓 / 加仓 / 减仓 / 清仓。

| 编号 | 不变量 |
|---|---|
| **INV-S3-6** | 推导**必须基于持仓状态的变化**，不得由单笔金额猜测 |
| **INV-S3-7** | 若源文件含**成交后证券余额**，可用单行判定：卖出且余额为 0 → 清仓；卖出且余额大于 0 → 减仓；买入且余额等于买入量 → 建仓；买入且余额大于买入量 → 加仓 |
| **INV-S3-2** | 若源文件**不含余额**，必须**按时间顺序回放**该标的在该券商的全部流水来推导 |
| **INV-S3-3** | 回放**必须按券商分组**，各券商的持仓状态互不影响 |
| **INV-S3-8** | 同日多笔且无法用余额区分时，**按该标的当日的先后顺序**依次推导 |
| **INV-S3-9** | 推导结果**必须可被用户修正**，修正后不再被自动覆盖 |

### 3.3 成交时间的语义

| 编号 | 不变量 |
|---|---|
| **INV-S3-10** | 成交时间的**唯一作用是区分同日多笔**，不参与任何业务计算 |
| **INV-S3-11** | 成交时间**可以为空**（当源文件不提供时）。现有「必填」约束是为手工录入设计的（防止同刻多笔），**对导入记录不适用** |
| **INV-S3-12** | 手工录入**仍保持「同日同标的同类型同时刻唯一」**（防重复提交），该约束**仅适用于成交时间非空的记录** |
| **INV-S3-13** | 同一标的同一天同一类型的**多笔必须可表达**（实测存在同一天同标的同方向多笔的成交） |
| **INV-S3-14** | 券商原始编号**不得作为唯一性依据**（§2.9.2） |

### 3.4 交易成本模型

| 编号 | 不变量 |
|---|---|
| **INV-S4-1** | 系统必须区分**毛盈亏**与**净盈亏**。所有面向用户的收益数字默认展示**净盈亏** |
| **INV-S4-2** | 成本项至少包括：佣金（含最低佣金）、印花税（仅卖出）、过户费、其他费用 |
| **INV-S4-3** | **佣金费率、最低佣金必须可按账户配置**。不同券商、不同客户等级费率不同 |
| **INV-S4-4** | **费率必须可按品种区分**。实测场内 ETF 佣金率显著低于股票 |
| **INV-S4-5** | 当源文件提供费用明细时，**以源文件为准**；缺失时才用配置费率反算，且反算结果须标注为「推算值」 |
| **INV-S4-6** | 费用明细**必须保留分项**，不得只存合计 |
| **INV-S4-7** | **最低佣金的影响必须在收益展示中可见**。实测小额成交的费用率可达大额成交的百倍量级 |

> 依据：某券商交割单实测，一笔 159.90 元的成交费用合计 5.00 元（成本率约 3.1%），
> 而同表一笔 15433.80 元的成交费用合计同为 5.00 元（成本率约 0.03%）。

### 3.5 现金类资产与风险资产

#### 3.5.1 分类定义

| 类别 | 范围 | 判定依据 |
|---|---|---|
| **风险资产** | 股票、股票 ETF、跨境 ETF、黄金 ETF、场内 LOF、债券 ETF、可转债 ETF | 默认归此类 |
| **现金类资产** | **国债逆回购**、**货币 ETF**、场内货币基金、活期结余 | **须由标的分类表显式标注**（见 §3.5.2） |

| 编号 | 不变量 |
|---|---|
| **INV-S4-8** | 系统必须区分**现金类资产**与**风险资产**，且该区分**必须可查询、可筛选、可分别统计** |
| **INV-S4-9** | 现金类资产**不参与**涨跌幅排名、不产生交易信号、不计入集中度分母、不进 RSI/择时计算 |
| **INV-S4-10** | 组合收益率**必须可拆分为「风险资产部分」与「现金类部分」**，且**总收益率口径必须与券商对账单一致**（含现金类收益与全部费用） |
| **INV-S4-11** | **「不作为交易」≠「不参与计算」**。任何被排除在交易记录之外的事件，若其收益影响账户总资产，**必须仍在收益计算中被计入或被显式归因** |
| **INV-S4-12** | 现金类资产的**分类不得由用户手工指定**。分类错误会直接导致收益率错误 |
| **INV-S4-13** | 现金类资产的**收益必须单列展示**，不得混入风险资产收益（用户需要看清「钱从哪来」） |

#### 3.5.2 标的分类必须可维护

现有行情层只区分 `stock / etf / index / bond / unknown / block / bstock`（实测），
**无法区分「货币 ETF」与「股票 ETF」**。因此需要一层**可维护的资产分类**：

| 编号 | 不变量 |
|---|---|
| **INV-S4-14** | 必须存在**标的资产分类**（风险 / 现金），且**可由规则初判 + 人工修正** |
| **INV-S4-15** | 分类初判**必须基于可验证的规则**（如：标的代码属于逆回购品种段；名称含「货币 ETF」且价格贴近面值），**不得仅凭名称关键词** |
| **INV-S4-16** | **人工修正必须优先于规则**，且修正记录**可追溯**（谁、何时、改了哪个标的） |
| **INV-S4-17** | 分类**变更后，历史收益必须可重算**（分类影响口径，不能只改当下） |

#### 3.5.3 国债逆回购的建模（实测口径）

实测华宝账户 180 对逆回购记录（1 天期，155 个交易日）：

| 实测项 | 值 |
|---|---|
| 利息合计 | **7,501.46 元**（= Σ收回金额 − Σ出资金额） |
| 在途本金 | 日均约 86.8 万，峰值 155.8 万 |
| 隐含年化 | 0.00558%/日 → **约 2.04%**（合理区间） |
| 占用天数 | 全部 0 天（1 天期，当日到期） |

**关键字段语义（与股票/ETF 完全不同，必须区别对待）**：

| 字段 | 股票/ETF | **国债逆回购** |
|---|---|---|
| 「成交价格」 | 每股价格（元） | **年化收益率（%）** —— 实测 1.465 表示 1.465% |
| 「成交数量」 | 股数 | **手数**（实测 14 手 ↔ 14000 元，即 1 手 = 1000 元） |
| 「成交金额」 | 价格 × 数量 | **实际资金额**（= 数量 × 每手面值） |
| 利息 | 无 | **= 收回金额 − 出资金额**（持有期产生的现金） |

> ⚠️ **把「成交价格」当单价处理是错的** —— 1.465 是收益率不是价格。
> 利息也**不是**任何一笔记录上的费用字段，必须由**配对**算出。

| 编号 | 不变量 |
|---|---|
| **INV-S4-18** | 逆回购的**报价字段语义为年化收益率**，与股票/ETF 的价格字段**必须区别处理**（§10 落 SDD） |
| **INV-S4-19** | 逆回购利息**必须由「收回金额 − 出资金额」配对计算**，不得用费率估算（实测配对误差为 0） |
| **INV-S4-20** | 配对**必须按同一标的、按时间顺序**（FIFO）进行。同日同标的多笔时**不得按数组顺序**配对（实测会错配） |
| **INV-S4-21** | 未配对的逆回购（出资无收回 / 收回无出资）**必须单独报告**，不得静默丢弃（可能是在途头寸或数据不全） |
| **INV-S4-22** | 逆回购**不产生价差盈亏**，其收益**全部是利息**。不得按买入/卖出的价差逻辑计算 |

#### 3.5.4 货币 ETF 的建模（实测口径）

实测同一标的的**两种操作、两种价格语义**：

| 操作 | 实测样例 | 金额/数量 | 价格语义 |
|---|---|---|---|
| 现金申购 | 511990 价 0.000 量 2100 额 210000 | **100.00** | **面值**（100 元/份） |
| 场内竞价卖出 | 511990 价 99.997 量 10900 额 1089967.3 | **99.997** | **市价** |

> 实测另见：511990 在 99.997 ~ 100.047 间波动（振幅约 0.05%）。
> **这意味着货币 ETF 的「涨跌幅」是极小量级，按价格四舍五入计算会产生显著失真。**

| 编号 | 不变量 |
|---|---|
| **INV-S4-23** | 货币 ETF 的**现金申购价（面值）与场内市价必须区分**。成本价 = 实际支付额 ÷ 份额，**两者混用是正确的**（移动加权成本天然处理），但**不得把价格字段当作可比较的涨跌幅基准** |
| **INV-S4-24** | 货币 ETF 的收益**必须按「市值变动」或「日结收益」口径计算**，**不得**用常规百分比涨跌幅（价格贴近面值，百分比口径失真） |
| **INV-S4-25** | 货币 ETF 的**场内与场外操作**在交易类型上可同为 `buy`/`reduce`，但**必须保留操作来源**（申赎 / 场内买卖），以便区分「按面值」与「按市价」 |
| **INV-S4-26** | 货币 ETF 的**申赎杂项**（现金替代退款、现金差额扣款等）**必须归入现金类收益**，不得作为独立交易，也不得丢弃 |

#### 3.5.5 收益率口径

| 口径 | 定义 | 用途 |
|---|---|---|
| **风险资产收益率** | (风险资产浮盈 + 已实现盈亏 + 现金分红) ÷ 风险资产成本 | 看选股与择时能力 |
| **现金类收益率** | (逆回购利息 + 货币 ETF 市值变动) ÷ 现金类投入 | 看资金管理效率 |
| **总收益率** | (总资产 − 总投入 − 累计费用) ÷ 总投入 | **与券商对账单对齐**，用户看到的默认口径 |

| 编号 | 不变量 |
|---|---|
| **INV-S4-27** | 三个口径**必须同时可查**，且**总收益率 = 风险资产 + 现金类 − 费用**（可加性必须成立） |
| **INV-S4-28** | **累计费用必须从总收益中扣除**，含最低佣金影响（实测小额成交成本率可达 3.13%） |
| **INV-S4-29** | 收益率的**分母定义必须明确**（成本口径 vs 投入口径），并与券商口径的差异在 UI 上标注 |

### 3.6 送股与现金分红的成本语义（V3.0 前置修复）

#### 3.6.1 现状缺陷（实测）

| 事实 | 后果 |
|---|---|
| 上层把 `dividend` / `bonus` / `transfer` 统一映射为「不参与成本计算」并忽略 | **送股不增加持仓股数** |
| 除权模块的历史持仓计算**把送股计为 +quantity** | 与上层口径**相反** |
| 核心成本算法只接受买 / 卖两种方向 | 无法表达「股数不变但成本被摊薄」 |

实测样例：某标的当日同时发生**送股 60 股**与**现金分红 34.00 元** ——
系统算出的持仓股数因此少 60 股，且分红收入为 0。

#### 3.6.2 业务规则（owner 决策：扩展核心算法，而非仅在上层打补丁）

| 事件 | 股数 | 总成本 | 成本价 | 现金 | 价差盈亏 |
|---|---|---|---|---|---|
| **送股 / 份额折算**（`bonus`） | **增加** n 股 | **不变** | 按比例**摊薄**：`新均价 = 原均价 × Q / (Q+n)` | 不变 | **不产生**（送股本身不是盈亏） |
| **现金分红**（`dividend`） | 不变 | 不变 | **不变** | **增加** = 股数 × 每股分红 | **不产生** |
| 二者同日发生 | 依次应用，先送股后分红（分红基数以送股后股数为准） | | | | |

> 与用户既有手工复盘表一致：该表将「盈亏金额」与「净利润」分列 —— 即**价差盈亏**与
> **含分红的净利**是两个不同的数。系统必须同样区分这两个口径。

| 编号 | 不变量 |
|---|---|
| **INV-S4-30** | 送股**必须增加持仓股数**，且**总成本不变**、成本价按比例摊薄 |
| **INV-S4-31** | 现金分红**必须增加现金**（= 股数 × 每股分红），且**不改变股数与成本价** |
| **INV-S4-32** | 送股与现金分红**本身不产生价差盈亏**。价差盈亏与含分红的净利**必须分别呈现** |
| **INV-S4-33** | 同日送股与分红**按「先送股、后分红」顺序应用**，分红基数为送股后股数 |
| **INV-S4-34** | **核心算法层必须支持上述两类事件**，不得仅在上层预处理。核心与上层的口径**必须一致**（消除现存的两处相反口径） |
| **INV-S4-35** | 摊薄后的成本价**必须用于后续卖出的已实现盈亏计算** |
| **INV-S4-36** | 现金分红的「每股分红额」与成交价**语义必须分离**，并在字段说明中明确（见 §3.1） |

## §4 策略体系与信号生命周期（S3）

### 4.1 策略分类

现有内置插件 4 个（RSI、MACD、均线多头、放量突破），无分类体系。

| 类别 | 说明 | 典型 |
|---|---|---|
| **趋势类** | 方向与强度 | 均线排列、MACD 金叉死叉、ADX、均线斜率 |
| **动量类** | 超买超卖 | RSI、KDJ、CCI、威廉指标 |
| **波动率类** | 通道与带宽 | 布林带、ATR 通道 |
| **量价类** | 成交确认 | 放量突破、缩量回调、量价背离 |
| **形态类** | K 线形态 | 锤子线、吞没、缺口、双底 |
| **风险类** | 仓位与止损 | ATR 止损、最大回撤、组合暴露 |

| 编号 | 不变量 |
|---|---|
| **INV-S3-15** | 每个策略**必须归属且仅归属一个类别** |
| **INV-S3-16** | 策略**必须声明其适用周期**（日线 / 60 分钟 / 15 分钟） |
| **INV-S3-17** | 策略**必须声明其适用品种**（全部 / 仅股票 / 仅场内 ETF / 仅跨境 ETF / 排除跨境等） |

> 依据：实测持仓以场内 ETF 为主且含跨境 ETF。跨境 ETF 跟随境外市场，
> A 股交易时段其流动性与定价机制不同，**用与 A 股 ETF 相同的参数评估其信号是无意义的**。

### 4.2 策略组合

| 编号 | 不变量 |
|---|---|
| **INV-S3-18** | 策略**必须可组合**（多个基础条件同时成立才出信号），而非每种组合各写一个策略 |
| **INV-S3-19** | 组合策略的**每个条件可独立开关与调参** |
| **INV-S3-20** | 策略参数**必须具名、必须声明取值范围与默认值**，禁止魔法数 |
| **INV-S3-21** | 策略的**默认参数必须来自可解释的依据**（如同类主流软件的默认口径），不得凭直觉设定 |

### 4.3 信号生命周期

现有信号表只进不出，会无限累积。

| 编号 | 不变量 |
|---|---|
| **INV-S3-22** | 信号**必须有过期语义**。信号不是永恒事实，过期后须标记为「已过期」而非删除 |
| **INV-S3-23** | **冷却期**：同一策略 + 同一标的 + 同一方向，在 N 根 K 线内**不得重复产生信号**（N 可配置，默认 3） |
| **INV-S3-24** | 信号**必须分级**（强 / 中 / 弱），默认只推送强信号 |
| **INV-S3-25** | 每日推送**必须有 Top N 摘要**，不得把全部信号倾泻给用户 |
| **INV-S3-26** | 信号**必须可回溯当时的输入数据**（触发时的 K 线、指标值），否则事后无法复核 |
| **INV-S3-27** | 用户对信号的**采纳 / 忽略操作必须被记录**，它是 §5 评估闭环的输入 |

### 4.4 信号与交易的关联

| 编号 | 不变量 |
|---|---|
| **INV-S3-15** | 信号与实际交易**可手动关联**；系统**不得自动宣称**某笔交易源自某条信号（除非用户确认） |
| **INV-S3-16** | 关联后，信号页可直接跳转该笔交易的复盘记录 |

## §5 策略有效性评估（S5）

### 5.1 目标

把「哪个策略有效」从主观判断变成**可计算的事实**。

### 5.2 评估方式

**采用信号复盘（signal review），不做模拟回测。**

| 编号 | 不变量 |
|---|---|
| **INV-S5-1** | 评估必须基于**真实产生的历史信号**与**真实后续行情**，不使用模拟成交 |
| **INV-S5-2** | 评估必须扣除**真实交易成本**（§3.4），且按该笔的实际金额计算最低佣金影响 |
| **INV-S5-3** | 评估必须产出**多周期结果**（T+1 / T+5 / T+10），并给出胜率、平均收益、最大回撤 |
| **INV-S5-4** | 评估必须**与基准对比**（否则胜率无意义） |
| **INV-S5-5** | 信号若在生效前已失效（如止损触发），必须按**实际可成交价**评估，不得用信号价 |
| **INV-S5-6** | 评估结果**必须可按策略 / 参数 / 品种 / 周期分组**下钻 |

### 5.3 反馈闭环

| 编号 | 不变量 |
|---|---|
| **INV-S5-7** | 用户对信号的**采纳 / 忽略标注必须被保留**，并可作为评估的补充维度（人工判断与量化结果分开呈现，不混算） |
| **INV-S5-8** | 量化评估与人工标注**分别呈现**，系统**不得用人工标注改写量化结论**，也不得用量化结论改写人工标注 |

**决策（2026-10-20，owner）**：**不纳入 V3**，转 V4 候选。

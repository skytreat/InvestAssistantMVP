# 个人投资助手 — 纯净需求规格文档（Requirements Simplified）

**版本：V1.0**
**日期：2026-10-14**
**文档定位：本文件从原始需求规格中剥离全部技术实现细节，聚焦「系统做什么（WHAT）」而非「系统如何实现（HOW）」。所有技术选型、架构决策、代码实现路径均不属于本文件范畴。**

---

## 1. 系统定位

面向 A 股 / ETF 个人投资者的**纯 Web 单中心投资管理工具**。用户通过浏览器（桌面端或手机端）直接访问统一入口。

系统仅提供数据记录、行情计算、条件判断与结果展示，**不自动交易、不对接实盘券商、不构成任何投资建议**。

---

## 2. 核心设计目标

| 目标 | 衡量指标 | 说明 |
|------|---------|------|
| 记账绝对精准 | 移动加权平均成本核算零计算误差，手续费口径全局唯一 | 业务规则保持稳定 |
| 行情可信 | 使用公开、免费、无限流的全市场日线数据源 | 替代传统付费接口 |

| 插件可扩展 | 插件化策略引擎，MVP 内置 2 个策略，**架构预留 50+ 策略扩展容量** | 新增策略不应修改核心引擎 |
| 双端一致 | 核心算法逻辑复用；桌面端与手机端展示结果一致 | 统一前端体验 |

| 备份可靠 | 行情数据（可重建）与业务数据（不可重建）分级备份 | 数据恢复可验证 |

| 收益透明 | **双口径收益统计**：价格收益率 + 实际收益率（含分红送转现金流入） | 满足不同分析场景 |

## 3. 系统约束（产品层）

1. **单中心 Web 应用**：所有组件集中部署，浏览器直接访问；无桌面端独立程序、无离线模式
2. **仅日线周期**：不支持分钟级、盘中实时行情与信号
3. **行情数据本地存储**：行情数据存储于服务器本地，不经过第三方中间服务
4. **HTTPS 安全访问**：全程加密传输
5. **仅面向个人用户**：不支持多租户、团队协作、机构账户

10. **三层数据完整性防线**：内部一致性校验（必过）+ 跨源原始数据校验（每日限次免费）+ 跨源复权数据校验（免费无限制）
11. **管理员角色**：首个注册用户自动成为管理员；管理员拥有额外管理权限
12. **收盘后定时自动化**：行情更新 → 数据校验 → 信号生成 + 资产快照 → 除权自动导入 → 双库备份，按序执行
13. **分级备份策略**：行情数据（可重建）保留周期短（本地 7 天 + 远程 90 天），业务数据（不可重建）保留周期长（本地 30 天 + 远程 90 天）；支持恢复验证
14. **用户鉴权**：注册/登录 + Token 机制 + 角色检查

## 5. 核心业务规则

### 5.1 交易类型（7 种，MVP 全部交付）

支持：买入、加仓、减仓、清仓 + **分红、送股、转增**。所有交易永久留痕，**不可物理删除**，**支持软删除标记**（标记为已删除后在列表中隐藏，但可恢复或审计查看）。

| 类型 | 操作 | 触发方式 | 操作理由 | 对持仓的影响 |
|------|------|---------|---------|-------------|
| 买入 | 新开买入 | 用户手动 | 用户填写 | 增加数量 + 移动加权成本 |
| 加仓 | 追加买入 | 用户手动 | 用户填写 | 增加数量 + 移动加权成本 |
| 减仓 | 部分卖出 | 用户手动 | 用户填写 | 减少数量（不超持仓），成本不变 |
| 清仓 | 全部卖出 | 用户手动 | 用户填写 | 数量减至 0，成本重置 |
| **现金分红** | **股息入账** | **系统自动导入 + 用户可手动补充** | 系统自动标注「系统导入 - {除权日} 除权除息」 | **不改变持仓数量；现金流入计入实际收益** |
| **送股** | **红股入账** | **系统自动导入 + 用户可手动补充** | 系统自动标注「系统导入 - {除权日} 送股」 | **同比例增加数量，均价不变（稀释）** |
| **转增** | **转增股入账** | **系统自动导入 + 用户可手动补充** | 系统自动标注「系统导入 - {除权日} 转增」 | **同比例增加数量，均价不变（稀释）** |

所有分红/送转交易记录需标记来源（系统自动 or 用户手动补充），前端 UI 以不同标签展示，用于风险排查。

**自动导入兜底**：绝大多数除权事件由系统自动导入，用户无需手动操作。如自动导入遗漏或失败，用户可手动补充；管理员也可手动触发补跑。

**幂等规则**：系统自动导入时，如已存在相同除权日、相同类型的记录（无论来源），则跳过不重复写入。

### 5.2 强制业务约束

每笔交易分两类处理：

- **买入/加仓/减仓/清仓**：用户**必须填写操作理由**（前端 + 服务端双重校验），不允许留空
- **分红/送股/转增（用户手动补充）**：操作理由**由系统固化自动写入**，格式为「人工补充 - {除权日} {类型}」，前端表单中理由字段**置灰不可编辑**，用户仅需填写除权日、金额/比例等数值字段

**减仓/清仓持仓充足性校验（服务端强制）**：减仓/清仓数量不得超过当前实际持仓：
- 前端预校验：超持仓 → 禁用提交按钮
- 服务端二次校验：校验失败拒绝写入
- 校验目的：交易永久留痕，负持仓脏数据一旦写入将永久污染聚合结果

**复盘补充字段（交易后填写，非必填）**：每笔交易预留 4 个复盘字段，交易录入时留空，**复盘时由用户手动填写**：
- 复盘总结（做对/做错的地方）
- 是否符合交易系统（三态：是/否/未标记）
- 是否止损（三态：是/否/未标记）
- 备注

### 5.3 持仓成本与手续费口径

1. **成本算法**：移动加权平均法，全系统统一
2. **买入手续费**：计入总成本，摊薄平均成本
3. **卖出手续费**：仅抵扣本次卖出盈亏，**不影响剩余持仓成本**
4. **送转股处理**：送股/转增类型交易**只增加持仓数量**，均价不变（同比例稀释）
5. **分红处理**：分红类型交易**不改变持仓数量和成本**，现金流入单独计入实际收益统计
6. **持仓数据由交易记录实时聚合计算**，不冗余存储快照

**移动加权平均成本公式**：
```
新均价 = (原持仓数 × 原均价 + 买入数 × 买入价 + 买入手续费) / (原持仓数 + 买入数)
```

**边界 case 处理**：
- 减仓/清仓：只减少持仓数量，均价不变
- 减仓/清仓数量 > 当前持仓 → **服务端拒绝保存**
- 清仓后再买：均价重置为首次买入价
- 持仓数为 0 时买入：等同于首次建仓
- 送转后再买入：送转数量计入「原持仓数」，加权正常计算
- 分红后再买入：分红不影响成本

### 5.4 收益统计口径（双口径，复盘页可切换）

**口径 1：实际收益率（默认，用户关心的真实收益）**
```
实际收益率 = (现价市值 + 累计分红现金流入 + 送转后新增市值 - 原始投入成本) / 原始投入成本
```
- 包含所有分红现金流入 + 送转后的市值变化
- 最接近证券账户 App 显示的实际盈亏

**口径 2：价格收益率（技术分析参考）**
```
价格收益率 = (现价市值 - 原始投入成本) / 原始投入成本
```
- 使用前复权价格计算
- **不含分红现金流入**
- 适合看价格波动、技术信号触发时的盈亏

### 5.5 策略引擎规则（插件化，50+ 预留容量）

#### 插件接口契约（高层描述）

每个策略插件必须声明：
- **唯一标识**：全系统唯一，不可变
- **展示名称 + 版本号 + 作者**
- **周期**：MVP 固定为日线
- **分类**：监控类（monitor）/ 筛选类（filter）
- **归属子分类**：动量 / 趋势 / 量能 / 突破 / 均值回归 / 形态 / 自定义
- **执行复杂度标记**（用于日志统计，非硬约束）
- **参数配置 Schema**（前端动态渲染配置表单）
- **默认参数值**
- **图表渲染元数据**（K 线图上的副图/叠加层渲染配置）
- **核心计算方法**：接收前复权日线序列 + 用户配置参数，返回信号对象；返回空表示「无信号」

**信号对象包含**：
- 方向：买入 / 卖出 / 持有
- 标签（描述性文字）
- 强度（可选，数值）
- 指标明细（可选，数值键值对）

#### 指标计算位置

**核心指标算法在两处计算，数值必须完全一致**：

| 位置 | 场景 | 时机 |
|------|------|------|
| 服务端定时任务 | 每日收盘后自动生成终态信号 | 收盘后批量执行，结果持久化 |
| 前端 K 线图 | 用户交互式探索指标参数 | 页面加载 / 用户改参数时实时计算 |

#### 插件目录与加载机制

| 规则 | 说明 |
|------|------|
| **内置插件库** | 打包在系统内，开箱即用；**MVP 仅包含 RSI + MACD 2 个默认插件**；引擎按 50+ 容量设计（子分类、复杂度、图表元数据） |
| **用户自定义插件** | 用户可在指定目录放置自定义插件文件，系统加载即可生效 |
| **加载时机** | 服务启动时扫描加载；Web 页面【设置 → 策略插件管理】可手动触发热重载 |
| **唯一键**：以插件唯一标识为键，内置与自定义不可冲突 |
| **故障隔离**：单个插件执行异常 → 标记该插件本轮跳过、记录日志、**不影响其他插件和主流程** |
| **超时保护**：单插件执行有硬限制（避免异常插件拖垮整体）；超时标记为异常，跳过本轮 |
| **批量调度**：收盘信号生成时，同一标的的日线数据一次加载、多插件共享（避免重复查询） |

#### 内置默认插件清单

| 插件标识 | 分类 | 子分类 | 名称 | 默认参数 | 信号触发逻辑 |
|---------|------|--------|------|---------|------------|
| rsi | 监控 | 动量 | RSI(14) 超买超卖 | period=14, oversold=30, overbought=70 | RSI < oversold → 买入；RSI > overbought → 卖出 |
| macd_cross | 监控 | 趋势 | MACD 金叉死叉 | fast=12, slow=26, signal=9 | DIF 上穿 DEA → 买入；下穿 → 卖出 |

> ⚠️ **分类为单值（monitor / filter 二选一）**，与 SDD §3.2 的
> `CHECK (category IN ('monitor','filter'))` 一致。
> 初稿曾把 `rsi` 写成「监控 + 筛选」双分类，与同文件「分类：监控类/筛选类」的表述冲突，
> 已于 2026-10-17 修正。**筛选类插件是独立插件，不是监控类插件兼任。**

#### 信号状态机与收盘固化

1. **监控覆盖范围**：用户自选列表 + 持仓列表的并集（去重，排除已软删除关联）
2. 以「标的 + 插件标识 + 周期」为独立状态单元
3. 仅状态由不满足 → 满足的**瞬间**生成一次信号，持续满足不刷屏
4. 日线行情数据异常时**不改变状态、不发假信号**
5. 信号**收盘后直接生成终态**（无盘中临时态，不做分钟级防抖）
6. **写入前置条件**：信号生成必须等待行情更新完成后才触发，确保基于最新数据
7. **单日唯一防重**：单日同一标的 + 同一插件仅留存一条有效信号，靠系统级唯一性约束天然防重，**不需要进程内防抖**
8. **收盘固化**：每日收盘后固化当日所有终态策略信号，用于复盘统计、胜率计算；杜绝单日多条重复信号干扰复盘归因

> **为什么不做盘中防抖？** 防抖适用于盘中实时数据（秒级 tick、分钟级 K 线），防止临时抖动导致信号频繁切换。日线收盘数据每天仅一次，不存在抖动可能，系统级唯一约束足以防重。

### 5.6 停牌日处理

行情数据源没有专门的停牌表，通过以下规则推断：
- 停牌日 = 交易日历标记为交易日，但行情数据没有对应日线（或价格/成交量为 0 的占位行）

**策略引擎对停牌的处理**：停牌日没有新的日线数据 → 插件拿到的日线序列最后一根停留在停牌前 → 状态机自然维持，不生成新信号。**不需要硬编码停牌日跳过逻辑**。

### 5.7 筛选与候选池

1. 独立于自选列表，用于评估选股策略胜率与稳定性
2. **MVP 支持手动加标的**：输入标的代码 + 加入理由即生成跟踪记录；基准价 = 加入日前复权收盘价
3. 每次筛选/加入固化「基准价」，同一标的多次跟踪生成多条独立记录
4. 迁移自选时可选择：复用基准价 / 使用当前现价；MVP 迁移自选时**只打标记**，不自动创建自选关联

### 5.8 行情数据质量规则

| 规则 | MVP 处理 |
|------|---------|
| 主键天然去重 | 行情数据主键 = (标的代码, 交易日)，天然幂等 |
| 停牌日推断 | 交易日历标记为交易日但行情无数据 → 停牌；策略引擎自然维持状态 |
| 交易日判定 | 使用精准交易日历，不依赖「日线行数 > 0」等替代方案 |
| 退市/ST 过滤 | 行情数据源自带的品种分类字段 |
| 除权除息 | 行情数据源原生处理，前复权价自动连续；除权事件供除权自动导入使用 |
| 行业/板块过滤 | 行情数据源自带的行业/概念/板块定义与成分关系 |
| 免费/限流 | 完全免费，无限流 |

### 5.9 鉴权规则（双角色）

| 角色 | 权限 |
|------|------|
| **普通用户（默认）** | 交易、持仓、行情、信号、选股、复盘、候选池、插件管理、**查看校验结果（只读）**|
| **管理员** | 普通用户全部权限 + **手动触发行情更新** + **查看每日校验日志详情** + **查看系统日志文件**（数据库损坏时的降级日志）+ **手动备份** + **恢复备份** + **升级/降级其他用户角色** |

**首用户自动成为管理员**：首个注册的用户自动拥有管理员权限。后续注册默认角色为普通用户。管理员可在设置页升级/降级其他用户角色。

## 6. 核心业务流程（用户视角）

### 6.1 每日收盘自动化（5 段，按序执行）

```
收盘后自动化时间线（相对顺序，精确时间由系统调度决定）：

  Step 1 行情数据更新
         ├── 增量更新日线行情（不复权）
         ├── 更新后复权因子
         ├── 更新股本变迁（除权除息事件）
         ├── 更新假期日历
         └── 更新板块/概念/行业信息
         → 行情数据准备完毕

  Step 2 数据校验
         ├── 内部一致性校验（8 项，秒级）
         ├── 跨源原始数据抽样校验（外部数据源，限次免费）
         ├── 跨源复权数据抽样校验（外部数据源，免费无限制）
         ├── 结果持久化保存（12 条记录，每条含 PASS/WARN/ERROR/SKIP）
         ├── WARN 级别：自动触发行情更新补跑
         └── ERROR 级别：记录 + 管理员告警

  Step 3 信号生成 + 资产快照
         ├── 查找所有用户的自选 + 持仓标的并集
         ├── 批量加载前复权日线
         ├── 加载所有启用的监控类插件
         ├── 批量执行插件 + 状态机判断 → 终态信号
         ├── 批量写入信号表
         └── 生成当日资产快照（用户可选择价格收益率口径或实际收益率口径，快照同时包含双口径）

  Step 4 除权自动导入
         ├── 查找最近除权事件
         ├── 判断用户是否在除权日持股
         ├── 生成分红/送股/转增交易记录
         └── 幂等检查后写入（已存在相同记录则跳过）

  Step 5 双库备份
         ├── 行情数据：压缩备份（体积较大，可重建，本地保留 7 天）
         └── 业务数据：完整性检查 + 热备份（不可重建，本地保留 30 天）
         → 上传至远程存储，远程保留 90 天，定期自动清理过期备份
```

### 6.2 交易记账流程

**买入/加仓/减仓/清仓（手动）**：
1. 用户在前端输入交易信息，**操作理由必填**
2. 前端预校验（减仓/清仓不超持仓、操作理由非空）
3. 请求后端 API
4. 后端服务端二次校验：持仓充足性、操作理由非空
5. 写入交易记录 + 更新持仓移动加权成本（事务）
6. 校验失败 → 返回具体错误码 → 前端提示

**分红/送股/转增（用户手动补充）**：
1. 用户在前端选「除权补充」入口，输入标的代码 + 除权日 + 金额/比例
2. 前端校验（标的必须在自选/持仓里、除权日格式）
3. 请求后端 API（与普通交易同一路由，但交易类型不同）
4. 后端自动填充：操作理由固化为「人工补充 - {除权日} {类型}」 + 标记为用户手动
5. 独立事务写入
6. 前端 UI 标签显示「人工补充」（灰色）

**分红/送股/转增（系统自动导入）**：
见 6.1 Step 4 详细流程。自动导入的记录标记为系统自动（is_auto_import=true 语义），操作理由按类型标注为「系统导入 - {除权日} 除权除息 / 送股 / 转增」（详见 §5.1 表格），前端 UI 标签显示「系统导入」（绿色）。

### 6.3 除权自动导入流程

1. 系统定时触发（收盘后自动化 Step 4）
2. 查找最近除权事件（除权日晚于用户最后一次除权导入日期）
3. 对每条事件，查找所有持有该标的的用户
4. 计算用户除权日前一日的持仓数量（交易历史聚合）
5. 生成交易记录：
   - **分红**：数量=0，价格=0，现金流入 = 持仓数 × 每股分红
   - **送股**：数量 = 持仓数 × 送股比例，价格=0，同比例稀释（均价不变）
   - **转增**：数量 = 持仓数 × 转增比例，价格=0，同比例稀释
6. **幂等检查**：写入前先查是否已存在相同除权日、相同类型的记录（无论来源），已存在则跳过，避免重复写入
7. 写入完成后更新用户的「最后除权导入日期」游标（避免下次重复扫描历史）

### 6.4 日线策略信号生成流程

1. 收盘后自动化 Step 3 触发
2. 查找所有用户的自选 + 持仓标的并集
3. 批量加载前复权日线
4. 内存构建日线序列 + 插件参数
5. 遍历所有启用的监控类插件：执行 → 状态机判断 → 决定是否写信号
6. 批量写入（1 个大事务），联合唯一约束防重

### 6.5 全市场选股流程

1. 用户选择筛选类插件 + 配置参数
2. 前端发送选股请求
3. 后端查询行情数据，执行筛选
4. 返回不超过 100 条结果，支持分页
5. 用户可【加入候选池】或【加入自选】

### 6.6 管理员手动触发行情更新

1. 管理员在设置页点击手动触发
2. 后端执行行情更新（有最大等待时长）
3. 更新成功后**立即触发**完整的收盘后自动化流程（校验 → 信号生成 → 除权导入 → 备份）
4. 结果持久化保存，前端显示进度
5. 当日已成功执行过 → 返回提示，需要管理员二次确认

## 7. 数据质量保障（12 项每日自动校验）

> ⚠️ **层界（2026-10-17 确立）**：本章定义 **C1-C12「要检什么」（业务要求）**，
> **具体 SQL 实现见 [SDD.md §5.7](SDD.md)** —— 技术契约由 SDD 独家承载，本章不写 SQL。
> 二者曾长期不一致（SDD §5.7 的 C3-C8 原本定义为「数据内容校验」，
> 而本章定义为「数据新鲜度」），已于 2026-10-17 裁决按本章为准（DEC-13 / B-14）。
> ⚠️ 本章定义的能力**永远只有 12 项**；其他有价值但未列入主表的检查，
> 归入 SDD §5.7「扩展校验」，不占 C 编号。

### 7.1 内部一致性校验（8 项，每日必过）

| # | 校验项 | 检查方式 | 失败级别 | 自动处理 |
|---|--------|---------|---------|---------|
| C1 | 日线行数正常 | 当日标的数 ≥ 3000（正常 5000+）| ERROR | 自动触发行情更新补跑 |
| C2 | 交易日历匹配 | 交易日标记为交易日的日期有日线数据 | ERROR | 自动触发行情更新补跑 + 交易日历重下 |
| C3 | 复权因子更新时间 | 最新日期 = 当日 | WARN | 自动触发行情更新补跑 |
| C4 | 除权除息更新时间 | 最新除权日 ≥ 当日 - 7 天 | WARN | 自动触发行情更新补跑 |
| C5 | 板块数据完整 | 总量稳定（降幅 < 10%）| WARN | 记录，人工确认 |
| C6 | 市值数据存在 | 当日标的数 ≥ 3000 | WARN | 自动触发行情更新补跑 |
| C7 | 日线价格合理性 | 收盘价 ≠ 0 且 开盘价 ≤ 收盘价 × 2 | WARN | 记录异常标的 |
| C8 | 行情更新执行时长 | 在合理范围（≤ 120s）| WARN | 记录 |

### 7.2 数学一致性校验（2 项）

| # | 校验项 | 检查方式 | 失败级别 | 自动处理 |
|---|--------|---------|---------|---------|
| C9 | **复权因子数学一致性** | 前复权收盘价 ≈ 不复权收盘价 × 复权因子（抽样 100 只，容差 < 0.01 元）| ERROR (>0.1) / WARN (0.01-0.1) | ERROR 触发行情更新补跑 |
| C10 | **除权日事件交叉验证** | 除权日价格跳变率 ≈ 除权事件参数（现金分红 + 送转比例）| WARN | 记录，人工确认 |

### 7.3 跨源校验（2 项，外部数据源）

| # | 校验项 | 数据源 | 抽样 | 容差 | 失败级别 |
|---|--------|--------|------|------|---------|
| C11 | **跨源原始数据** | 外部免费行情源（每日限 1 次免费机会，含前收盘价）| 30 只 | OHLC 完全一致或 <0.01 元；成交量 <1%；前收盘价合理 | >3 只不匹配 → WARN；>5 只 → ERROR |
| C12 | **跨源复权数据** | 东方财富公开接口（免费无限制）| 20 只 | 前复权收盘价 <0.02 元；后复权相对差异 <0.5% | >5 只有差异 → WARN；>1 只差异 >0.1 元 → ERROR |

**跨源校验鲁棒性策略**：
- 请求节流：每只标的之间短暂间隔
- 有限重试：每只最多 2 次（退避递增）
- 失败类型拆分：连接失败 → 跳过；被限流 → 跳过
- 上限保护：总请求数受限，总耗时 ≤ 30s
- 单标的超时保护
- 降级：外部源整体不可用（连续多只失败）→ 标记 SKIP，不阻塞整体流程

### 7.4 三层完整性防线

```
第一层：内部一致性（C1-C10，必过）
第二层：跨源原始数据（C11，每日限次免费，校验不复权 OHLCV + 前收盘价）
第三层：跨源复权数据（C12，免费无限制，校验前复权 + 后复权价）
三层全过 → 行情数据可信
任何一层 ERROR → 自动触发行情更新补跑 + 人工确认
```

## 11. 风险与应对

| # | 风险 | 概率 | 应对 |
|---|------|------|------|
| R1 | 行情数据损坏或丢失 | 低 | 每日分级备份；完整性校验早发现；可重新拉取 |
| R2 | 业务数据损坏 | 极低 | 热备份 + 多副本 + 定期完整性检查；从备份恢复可验证 |
| R3 | 定时任务执行失败 | 低 | 定时守护 + 多维度校验 + 自动补跑 |
| R4 | 自定义插件超时/异常 | 低 | 执行超时硬限制 + try-catch 隔离 |
| R5 | 行情数据源不可用 | 低 | 多数据源备选；付费接口兜底 |
| R6 | 跨源校验接口限流或不可用 | 低 | 标记 SKIP 不阻塞；节流策略避免触发限流 |
| R7 | 除权自动导入遗漏 | 低 | 幂等可重跑；管理员可手动触发补跑；交叉验证发现后告警 |
| R8 | 服务器不可用（含服务被终止） | 低 | 每日完整备份；换服务器 + 恢复备份可在 30 分钟内完成 |
| R9 | 网络访问延迟 | 极低 | 测试环境提前验证网络质量；备选网络加速方案可选 |

# DualMomentum（双动量轮动）策略说明

> 定位：**面向人读的入门说明**。判据、参数锁定表、偏差登记不在这里重复，需要时看第 8 节「文档地图」。
> 状态：L1 已实现并单测通过；已注册进回测 CLI 与纸面白名单；纸面按方案 D 降级（见 §5）。
> 记录时间：2026-11-10。

## 1. 这个策略在做什么

一句话：**在固定的 7 只 ETF 里按动量排序，只在趋势成立时持有排名靠前的几只，否则空仓。**

具体是三件事叠在一起：

- **横截面动量**：给 7 只标的各算一个动量分（默认是 25 根加权斜率动量 WSM V2），按分数降序取前几名，而不是预测大盘涨跌。
- **主槽 / 次槽**：主槽负责排序与「多强」，次槽是一道趋势质量过滤。默认组合 `wsm_v2_rsrs` = 主槽 WSM + 次槽 RSRS。
- **市场过滤**：把每只标的的主槽动量与沪深300 指数（`sh000300`）的同口径动量比，跑不赢基准的不买。这条是「双动量」里第二个「动量」的来源。

在 MVP 里的位置：回测 CLI 支持 `buy-and-hold` / `wufu-rotation` / `dualmomentum` 三种策略，它是**继五福轮动之后的第二个轮动策略**，与五福同属新的 `Strategy` 适配器框架（`defineStrategy`），不是老的插件式 `Plugin`。信号侧（`BUILTINS` / `routes/signal.ts`）**不实现**。

代码入口：

| 位置 | 职责 |
|---|---|
| `apps/backend/src/services/backtest/strategies/dualmomentum/index.ts` | 策略适配器与组合层（L2）：止损 / 止盈 / 再平衡 / 超配 / 买入预算 |
| `.../dualmomentum/l1/` | 指标、过滤链、排名（L1），**纯函数、零 IO** |
| `.../dualmomentum/params.ts` | 参数 schema；默认值引用 `l1/params.ts` 的锁定常量，不另抄一份数 |

## 3. 决策流程：哪天算、哪天买

### 3.1 时间轴

1. **T 日收盘后**：用截至 T 的 bar 算指标（默认需 60 根预热，不足则整体短路为 0）→ 逐只过滤 → 排名 → 定目标权重 → 产出「目标集合」。
2. **T+1 开盘**：由回测引擎按开盘价成交（适配器声明 `priceMode = 'open'`，不自己算成交价）。
3. 执行层的硬约束：停牌当日订单**失效且不顺延**；涨跌停「触及即算」不可成交；费用、滑点、手数取整都由引擎按参数执行。

### 3.2 过滤链（10 步短路，可归为四层）

| 顺序 | 层 | 规则 | 作用 |
|---|---|---|---|
| 1 | 池 | `POOL_ABSENT`（从未有 bar） | 未上市 / 不在池 |
| 2 | 可交易 | `SUSPENDED`（当日无 bar 或不可用） | 停牌 |
| 3 | 冷却 | `COOLDOWN`（止损后 3 交易日、止盈后 5 交易日内不重进） | 防止刚被打出来又买回 |
| 4 | 涨跌停 | `AT_LIMIT`（触及涨跌停价即不可成交） | 一字板买不进 |
| 5 | 异动 | `DAILY_CHANGE_OUT_OF_RANGE`（当日涨跌幅超出 ±5%，含 1e-9 容差） | 排除异动日 |
| 6 | 趋势 | `BELOW_MA20`（价格必须 `> MA20`） | 不买在均线下 |
| 7 | 多头排列 | `MA_NOT_BULLISH`（`MA5 > MA10 > MA20 > MA60`，全严格） | 趋势结构完整 |
| 8 | 动量区间 | `MOMENTUM_OUT_OF_RANGE`（主槽 ∈ [0,5]、次槽 ∈ [0,2]） | 双侧窄窗：太弱不买，过热也不买 |
| 9 | 市场过滤 | `BELOW_BENCHMARK`（主槽动量 ≥ `sh000300` 同口径动量） | 跑不赢基准不买 |
| 10 | 截断 | `RANK_TRUNCATED`（排名 > 6） | 只留前 `maxHoldings` 只 |

第 1–9 步任一不过即出局；第 10 步的标的仍算「过滤通过」，只是不入选。

### 3.3 主槽 / 次槽分工

- **主槽**：排序键 + 「多强」判断 + 与基准比较，默认 WSM V2（25 根加权斜率，年化后乘加权 R²）。
- **次槽**：默认 RSRS（25 根高低价回归斜率 × R²，再做 25 根 Z 值），设计意图是「趋势质量」这一层防御。
- 槽位名固定、量纲随 combo 变：`wsm_min/wsm_max` 作用在主槽，`rsrs_min/rsrs_max` 作用在次槽。默认 `wsm_v2_rsrs` 下二者分别就是 WSM 与 RSRS 的区间；另两种 combo（`nday_return_rsrs` / `nday_return_wsm_v2`）只用于历史对照。

⚠️ 次槽的实测表现远低于设计意图：RSRS 在 7 只横截面上几乎不提供排序信息，防御槽八年零持仓（见 §5、§6）。

### 3.4 出场有哪几种

按优先级从高到低（L2，`index.ts` 第 3 步）：

| 出场 | 触发条件 | 备注 |
|---|---|---|
| 成本止损 | 相对持仓成本跌幅 ≥ 10% | 成交后开 3 交易日冷却 |
| 高水位止损 | 自建仓后最高收盘回撤 ≥ 12% | 高水位在 qfq 空间维护 |
| 止盈 | 持有 ≥ 5 天且含费收益 ≥ 30% | 成交后开 5 交易日冷却 |
| 掉出候选 | 不在本期前 6 且持有 ≥ 5 天 | 对应 `out-of-candidate` |
| 超配减仓 | 单只市值占「持仓总市值」> 40% | 只减不加，分母**不含现金** |

买入侧：卖出后估算现金 ÷ 候选数均分，单只不超过总权益 33%；已持仓且本期不加仓的用 `hold` 表达，避免被引擎误判成减仓。

> 口径细节：`min_hold_days` 按**自然日**差计算（DAS §9.1 明确，参数描述也写「自然日」），不是交易日。冷却则按**交易日**计。

## 4. 与五福轮动的差别

| 维度 | 五福轮动（`wufu-rotation`） | 双动量（`dualmomentum`） |
|---|---|---|
| 框架 | 新 `Strategy` 适配器 | 同为 `Strategy` 适配器（二者同一套回测引擎） |
| 池 | 固定 114 只 ∪ 动态时点候选；走弱期换成弱池 | 硬编码 7 只，无动态、无走弱期池 |
| 市场判断 | A 股走弱期状态机；走弱期可持防御标的 `sh511880`（货币 ETF） | 与 `sh000300` 的动量比较 + 次槽过滤；**无走弱期状态机、无防御标的** |
| 行情输入 | 全市场 ETF 面板 + 动态池清单 | 7 只 ETF + 1 条指数（`sh000300`） |
| 输入缺失时的表现 | — | 缺 `sh000300` 时市场过滤退化为 `benchmarkPrimary = 0` 并打 warn |

**行情输入要求「更窄但更硬」**：标的少，却要求 7 只都带前复权因子、且额外要求一条指数轨（来自指数真实表 `class='index'`）。少这条指数轨策略不会崩，但会静默退化成「基准动量为 0」，判断口径已经不同。

### 4.1 两个「基准」不是同一个东西

| 字段 | 标的 | 用途 | 数据来源 |
|---|---|---|---|
| 策略内 `params.benchmark` | `sh000300`（指数，不可交易） | 过滤链第 9 步的市场过滤 | 指数真实表 |
| 纸面账户 `benchmark_asset_code` | `sh510300`（ETF，可交易） | 账户层展示与超额口径 | ETF 视图 `v_etf_*` |

二者**不是同一概念，不要合并、不要当 bug 修**。本文档与阶段 0 文档里说「跑赢 `sh510300` 多少 pp」指的是账户层超额，与策略内过滤用的 `sh000300` 无关。

## 5. 当前实现状态与已知限制

- **L1**：已实现，纯函数零 IO，由调用方注入行情切片；单测 **29/29**（指标 golden 8 + 过滤/排名 17 + CSV 4）。
- **注册**：已进回测 CLI（`--strategy dualmomentum`）与纸面白名单。信号侧不实现。
- **纸面账户按方案 D 降级**：公共回放路径在中间日使用空组合、不产生成交、不调 `onFill`，而本策略的 L2 状态（建仓日 / 高水位 / 冷却表）只能由成交事件累积。后果是**四条规则在纸面永不触发**：
  - 止盈（持有 ≥5 天且 ≥30%）
  - 再平衡 / 掉出候选
  - 高水位止损
  - 止损 / 止盈冷却

  纸面仍可用：成本止损（只读成本）、超配减仓（只读持仓市值）、选股与权重分配。
- 因此：**纸面结果不得与回测结果互相校验**，两者口径不同。纸面只用于验收三件事——能选中该策略、能读到参数 schema、能按当日上下文出一次决策。回测（`cli.ts backtest` + `optimize`）才是唯一有效验收入口。
- **A 方案（纸面全量成交模拟）已立项、未实施**；不在适配器或 `paper/decision.ts` 里打补丁。
- **L2 三条已知口径差**（都在 `index.ts` 头注释里）：`unit_cost` 取引擎移动加权成本、含买入费用（约 6bp 差）；手数取整由引擎按 T+1 实际开盘价完成；高水位在 qfq 空间维护，建仓首日按「成交价 × 当日 qfq/raw 比」换算。
- **次槽 RSRS 待重新设计**：实测 h=10 的 IC 0.003 / ICIR 0.006，2019–2023 段为负；防御槽八年零持仓。调 `rsrsMin` / `rsrsMax` 救不活（§6）。

### 为什么现在不建议做参数寻优

62 组一维扫描里**没有任何一档能跑赢 `sh510300`**，最好的一档（−0.86pp/年）还是靠关闭超配减仓规则换来的。原因不是「参数没调好」，而是三件事叠加：

1. **信号很弱**：WSM 的横截面 IC 只有 h=10 → 0.082 / ICIR 0.166，RSRS 基本没有（0.003 / 0.006）；
2. **横截面太窄**：只有 7 只标的，排序的区分度天然有限；
3. **地形非单调**：`wsmPeriod` / `rsrsPeriod` 的响应锯齿状，分段最优方向经常相反，收益高度集中在 2024–2026。

在「弱信号 + 窄横截面 + 非单调地形」上做网格搜索，选出来的必然是噪声。更值得做的是结构改动（次槽重新设计、用弱信号做部分仓位），而不是继续调参。完整数字见 `dualmomentum-dm-sweep-stage0.md` §9、§10。

### 7.1 已知实现分歧

以下条目**只取自已记录在案的结论**（DAS §9 / §10 与本轮对齐审计），不新增判断、不重新裁定对错：

| # | 条目 | Python 现状（记录在案） | MVP 做法 | 依据哪条 DAS |

两点读法：

- 「Python 现状」是**记录在案的历史状态**，本次未逐行复核 Python 侧当前代码；带「现有」字样的取自仓库内可见代码。
- **Python 侧后来改没改，不改变 MVP 的做法。** MVP 照抄的是 DAS 的结论（例如 #5 的 w² 是「确认选择」而不是修 bug，见 §3.2(a) 的记录方式）。

### 7.2 与 DAS 冲突处

- **成交时点、`price_model` 多值、停牌顺延、复权记账**：Python 侧与 DAS 不同，MVP 一律按 DAS §10「本规格」列执行（T+1 开盘、只接受 `t1_open`、停牌当日订单失效不顺延、bfq 账本）。
- **#2 的 `last_valid_close`**：与 DAS 裁定 D1 一致，但 DAS 明确标注这是「对齐选择，非数学唯一解」。
- **#5 的 w² / w**：DAS 记录的是「照抄并可追溯」，若日后判定另一口径才是本意，那是**重新确认选择**，不是修 bug——两端要同时改。

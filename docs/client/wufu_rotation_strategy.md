# 五福轮动 ETF v5.2 策略说明

> 定位：**面向人读的入门说明**。章节顺序参考同目录的 `dualmomentum_strategy.md` 与 v5.2 脚本结构，但每一节结论都按 MVP 的 `wufu-rotation` 实现重写，不照抄脚本注释。
> 状态：M3 日线主干已实现并通过 golden 逐位单测；已注册回测 CLI 与纸面白名单；M4 参数寻优结论为「不改默认参数」。
> 记录时间：2026-11-14。
> 效力边界：五福**没有独立的 DAS**。业务规则以仓库外只读脚本 `五福轮动ETF_v5.2.py` 为准；移植解释以 `docs/audit/wufu-etf-rotation-v5.2-feasibility-2026-11-06.md` §2/§8 为准；逐位实现由 `apps/backend/tests/fixtures/backtest/wufu-golden.json` 与 `backtest-m3-wufu.test.ts` 锁定。脚本与实现冲突时，先由报告判定是「有意偏差」还是「缺陷」，不得为“修正”而擅自改 golden。

## 1. 策略思路

一句话：**在一个 ETF 池里按「加权对数回归动量 × R²」打分，默认只持有一只；四指数走弱时切到全球池并改用 MA10 过滤，候选全空时退到防御 ETF。**

三件事叠在一起：

- **选池**：固定池 114 只 + 动态池（全市场流动性过滤后按行业分组取第一，top300）+ 防御 1 只（`sh511880`）。
- **打分与过滤**：25 日加权对数回归的斜率年化 × 混合口径 R²，再叠加分值区间、短期跌幅、量比、R² / MA10 等过滤。
- **市场状态**：四个 A 股指数对 MA10 投票，3/4 走弱进入「走弱期」，切全球池、关 R²、改用 MA10 过滤。

在 MVP 里的位置：回测 CLI 支持 `buy-and-hold` / `wufu-rotation` / `dualmomentum` 三种策略，**它是回测框架里的第一个轮动策略**，与双动量同属 `Strategy` 适配器框架（`defineStrategy`），不是老插件式 `Plugin`。纸面 `paper/strategies.ts` 的 `BUILTINS` 已登记 `(wufu-rotation, 5.2.0-m3)`；信号侧（`signalService.ts` / `routes/signal.ts`）**不实现**，也没有 API / UI。

## 2. ETF 标的池：三层，不是「一池到底」

| 层 | 规模 | 用途 | 关键口径 |
|---|---|---|---|
| 固定池 | 114 只 | 正常期基础池，与动态池合并 | 全球 17（商品 5 + 海外 12）+ 中国 97（港股 13 + 宽基 12 + 行业 72），再按流动性过滤 |
| 动态池 | top300（锚点日 140 组） | 正常期补充全市场新 ETF | 时点名录 → 排除词 → 名称清洗 → 前 2 字分组 → 组内成交额第一 → 全局成交额排序 |
| 走弱池 | 全球池 17 只经流动性过滤 | 走弱期替代合并池 | 不用「固定池 + 动态池」的合并池 |
| 防御 | 1 只 `sh511880` | 候选全空时持有 | 货币 ETF；停牌则空仓 |

**流动性阈值**：近 3 日全市场 ETF 成交额之和的日均 ÷ `20000`；近 3 日窗口不足 3 天时回退 **1000 万元**固定值。固定池、动态池、走弱池都要求日均额**严格大于**这个阈值（动态池只是候选来源，最终仍按成交额分组取第一）。

**锚点（T = 2026-10-12，可行性报告实测）**：

| 项 | 值 |
|---|---|
| 流动性阈值 | 3 日均总成交额 4345.2 亿元 / 20000 = **2172.6 万元/日** |
| 全市场通过 | **673** 只（同日有 bar 2074 只） |
| 固定池通过 | **112 / 114**（`sh520830` 沙特 ETF 1423.7 万、`sh516190` 传媒 ETF 1819.7 万未过） |
| 动态池 | **140 组**（top300 未触及） |
| 固定池库内命中 | **115 / 115**（含防御 1 只） |

**固定池的前视问题（严重）**：114 只是按 2026 年时点的流动性与上市状态人工筛选的，其中 **32 只（28%）2023 年后才上市**。用它回溯 2015–2020 等于「用今天的知识挑标的」，收益必然虚高。**固定池只用于 2023 年后的对照；长样本一律用时点池，并分段呈现。**

**名称与名录**：动态池的名字来自当前快照，不是 point-in-time；`raw_symbol_name` 中 ETF 名称约 **15.4% 有 U+FFFD 末字损坏**，约 **24.3% 的标的（多为停更残段）没有名称**（近一年活跃标的覆盖 99.8%）。分组键只取清洗后的前 2 个字，末字损坏通常不影响分组；但这是已知的轻度前视，不修正、只披露。

## 3. 动量打分

`calculate_momentum_score`（v5.2 L687–L711）的日线等效：

```text
y = ln(price[t-lookbackDays .. t])        # 默认 26 个点，末点 = asOf 收盘
x = 0 .. lookbackDays
weights = linspace(1, 2, n)                # 线性递增
W = weights^2                              # 平方；末端权重 4 倍于首端

slope = ΣW·(x−x̄)·(y−ȳ) / ΣW·(x−x̄)²   # x̄ / ȳ 是 W 加权均值
annualized = exp(slope × 250) − 1
r² = 1 − Σweights·(y−ŷ)² / Σweights·(y−mean(y))²
score = annualized × r²
```

**R² 是混合口径，不可「修正」**：残差平方和用 `weights` 加权，总平方和也用 `weights` 加权，但总平方和的中心是**无权均值** `mean(y)`。看起来像 bug，实际上是 v5.2 原样；改成标准加权 R² 会让分数整体漂移，golden 已锁死。

**点数与有效点**：

- 需要 `lookbackDays + 1` 个收盘（默认 26）；不足 26 返回 null。
- 第二条门槛 `prices.length < lookbackDays × 0.8`（默认 20）也返回 null。
- 历史序列按 `valid_mask` 剔除零成交量日（停牌），再由更早交易日补足；保留窗口 = `max(lookbackDays, volumeLookback, maLookback) + 20`（默认 45），装载窗口 = 同式 `+ 40`（默认 65 根日历 bar）。
- 有效点不足时**默认淘汰**（同 v5.2 L913），并记录 `lookbackInsufficient`（当日）/ `lookbackInsufficientTotal`（累计）。只有显式 `expandLookback=true` 才向前扩窗；这是有意偏离，默认关闭。

golden 夹具中的两个 26 点样例（Python oracle 逐位断言）：

| 场景 | annualized | r² | score |
|---|---|---|---|
| 稳定上涨 | 2.455975627 | 0.994243651 | 2.441838175 |
| 宽幅震荡 | 0.051608392 | 0.006302939 | 0.000325285 |

震荡序列的年化并不低，但 R² 接近 0，最终分数接近 0——这就是「涨得多且走得顺」的含义。

## 4. 过滤链

逐票短路，任一步不过即出局；顺序即优先级：

| 顺序 | 通过条件 | 不通过 |
|---|---|---|
| 1 | `asOf` 未停牌（有 bar 且 volume > 0） | 跳过 |
| 2 | 动量非 null 且有效点足够 | 跳过 |
| 3 | `minScore ≤ score ≤ maxScore`（默认 [0, 5]） | 淘汰 |
| 4 | 近 3 个涨跌幅均 `≥ lossThreshold`（默认 0.97） | 淘汰 |
| 5 | 量比非 null 且 `< volumeRatioThreshold`（默认 1.8） | 淘汰 |
| 6 | 正常期 `r² > r2Threshold`（默认 0.4） | 淘汰 |
| 7 | 走弱期 `close > MA(maLookback) × maThreshold`（默认 MA10 × 1.0） | 淘汰 |

边界口径（除分值区间为闭区间、短期风控为「等于也保留」外，其余均为严格不等号；恰好等于阈值时的结果）：

| 阈值 | 恰好等于阈值 |
|---|---|
| 动量分值区间 [0, 5] | 保留（闭区间） |
| 短期风控 `lossThreshold=0.97` | 保留（-3.00% 不淘汰） |
| 量比 `volumeRatioThreshold=1.8` | 淘汰（1.8 不通过） |
| 正常期 `r2Threshold=0.4` | 淘汰（0.4 不通过） |
| 走弱期 `maThreshold=1.0`（MA10） | 淘汰（等于 MA10 不通过） |

补充：

- 量比为 `null`（历史量不足或含 0）**直接淘汰**，不是「不拦截」。
- 停牌判定 = 缺 bar ∪ volume = 0；历史零量日先从序列剔除，再做打分与过滤。
- 正常期只看 R²，走弱期只看 MA10；两者不同时生效。
- 通过过滤后按 `score` 降序取前 10，同分按代码升序（决定论）；第 10 名之后仍算「过滤通过」，只是不进入候选。

## 5. 走弱期状态机

观察四个指数：`sh000300`（沪深300）、`sz399101`（小盘）、`sz399006`（创业板）、`sh000510`（中证 A500）。每个指数取 **11 个收盘**：最后一个为 current，后 10 个均值为 MA10。

| 规则 | 值 |
|---|---|
| 进入 | `belowCount ≥ 3` 且当前不在走弱期 |
| 退出 | `aboveCount ≥ 3` |
| 强制退出 | 连续走弱 ≥ `maxWeakDays`（默认 20）个交易日 |
| 持平 | `current == MA10` 既不算 below 也不算 above |
| 数据不足 | 该指数跳过，不计入投票 |

**20 日强退的实际行为（必须照抄，不要当 bug 修）**：已在走弱期时，分支顺序是「强退 → 退出 → 进入条件仍成立则把 `startDayIndex` 重置为今天 → 否则保持」。因此**只要 ≥3/4 指数仍低于 MA10，计数每天重置，20 日强退实际不会触发**；20 日只在「既不再满足进入条件、也未满足退出条件」（如 2 低 / 2 高）期间累积。这是 v5.2 的现状口径。

走弱期的影响：

- 池子从「固定池 ∪ 动态池」切到**全球池经流动性过滤**（默认 17 只以内）。
- 过滤链关闭 R²，改用 `close > MA10 × maThreshold`。
- 候选系数从 `0.9` 改为 `1.0`（候选池更窄）。
- `weakDays` 的展示值在重置后为 1（v5.2 为 0），只影响日志展示，不影响强退时机。

## 6. 候选、持仓保留与防御

**候选池**：

1. 过滤后按 `score` 降序取前 10（`CANDIDATE_TOP_ROWS = 10`）。
2. 参考分 = `top10[holdingsNum - 1].score`；如果 top10 不足 `holdingsNum`，全部 top10 都算候选。
3. 候选 = `score ≥ 参考分 × 系数`；系数正常期 `scoreThresholdRatio`（默认 0.9），走弱期固定 1.0。
4. `holdingsNum` 默认 **1**（全仓单只），上限 10；名字里的「五福」不代表固定持有五只。

**持仓保留**：

- 当前持仓 ∩ 候选（且不是当日止损标的）→ 保留，按 `score` 降序。
- 保留数 ≥ `holdingsNum` → 取前 N；不足 → 从其余候选按 `score` 顺序补足。
- 保留仓**不买不卖、不参与资金分配**（`hold: true`），不做市值再平衡。
- 顺序细节：v5.2 在「保留数 ≥ N」时按 score 降序，否则保留原持仓顺序再补足；MVP **始终**按 score 降序。N=1 时完全一致；N>1 只影响下单先后，不影响选出哪些标的。

**防御回退**：

- 候选为空且 `sh511880` 不停牌 → 目标为防御 ETF。
- 首次进防御时目标权重 100% = **吃满当时可用现金**；已持有防御则 `hold`，不再调整、不再补钱。
- 防御 ETF 当日停牌 → 当日目标为空，持仓在 T 开盘卖出后保持现金。
- 防御 ETF 是货币 ETF，不等同于「每日按权益再平衡到 100%」。

**止损**：

- 决策时按 `asOf` 收盘判定：`close ≤ avgCost × stopLossThreshold`（默认 0.95）→ 当日不进 targets。
- 若该标的已持有，则不在 targets 里，引擎在 T 开盘卖出；当日**不能再买回**。
- `avgCost` 是引擎的移动加权成本（含买入费用）；与 v5.2 的持仓成本口径存在小额费用差。

**退出原因**（M3 归因依赖）：`stop-loss` / `defensive-fallback` / `weak-period-exit` / `drop-from-pool` / `out-of-candidate`。

## 7. 每日执行时序与资金

**回测口径**：

1. **T-1 收盘后**：用截至 `asOf = T-1` 的行情构建时点池、打分、过滤、定 targets。
2. **T 开盘**：引擎按开盘价成交（策略声明 `priceMode: 'open'`）。
3. 引擎在运行时强制 `universe.asOf === T-1`，不一致直接抛错；策略上下文的所有读取都截止到 `asOf`，前视在接口层做不到。

**资金分配**：

- `buyBudget: 'remaining-cash-equal'`：先卖后买，每笔按「当前可用现金 ÷ 剩余待买只数」均分，最后一笔可取走剩余全部现金；现金低于 `minNotional` 停止买入。
- 已持有且保留的标的不计入「待买只数」，也不参与分配。
- 防御 ETF 首次进仓时是唯一待买标的，因此吃满可用现金；之后 `hold`。

**执行层规则**（`DEFAULT_TRADE_RULES`）：

| 项 | 默认 |
|---|---|
| 佣金 | 成交额 × 0.0001（万 1），双边，最低 5 元 |
| 滑点 | 0.0001（万 1），买 + / 卖 − |
| 印花税 / 过户费 | 0 / 0（ETF 口径；CLI 可覆盖） |
| 整手 | 100 份，向下取整；不足 100 份但现金够则按 100 份 |
| 最小成交额 | 10 元，低于跳过 |
| 涨跌停 | `preclose × (1 ± 10%)`；开盘价 ≥ 涨停买不进，≤ 跌停卖不出 |
| 停牌 | 缺 bar 或 volume = 0 → 当日该标的跳过 |
| T+1 | 当日买入不可卖，卖出量按可用持仓封顶 |
| 顺序 | 先卖后买（卖出释放现金后再买） |

基准默认 `sh510300`（账户层展示与超额口径）；策略内走弱期观察的是四个**指数**，防御标的是 `sh511880`，三者不要混淆。

## 8. 参数默认值与 CLI

| 参数 | 默认 | 范围 / 说明 |
|---|---|---|
| `holdingsNum` | 1 | 1–10；1 = 全仓单只；上限 = 候选行数 10 |
| `lookbackDays` | 25 | 5–120；实际取 `lookbackDays + 1` 个收盘 |
| `minScore` | 0 | -10–10；闭区间下限 |
| `maxScore` | 5 | -10–100；闭区间上限 |
| `r2Threshold` | 0.4 | 0–1；正常期要求 `r² >` 该值 |
| `maLookback` | 10 | 2–60；走弱期均线周期 |
| `maThreshold` | 1.0 | 0.5–2；走弱期要求 `close > MA ×` 该值 |
| `volumeRatioThreshold` | 1.8 | 0.1–20；量比 ≥ 该值淘汰 |
| `volumeLookback` | 5 | 1–60；过去 N 个交易日（不含 asOf）均量 |
| `lossThreshold` | 0.97 | 0.5–1；近 3 日任一涨跌幅 `<` 该值淘汰 |
| `scoreThresholdRatio` | 0.9 | 0–1；正常期候选系数；走弱期固定 1.0 |
| `maxWeakDays` | 20 | 1–120；名义强退天数，实际受每日重置影响 |
| `stopLossThreshold` | 0.95 | 0.5–1；`asOf` 收盘 ≤ 成本 × 该值清仓 |
| `defensiveEtf` | `sh511880` | 候选全空时的防御标的 |
| `expandLookback` | false | 有效点不足时是否向前扩窗；默认关闭，开启属有意偏离 |

`divisor` / `topN` **不在策略参数里**：它们属于 universe 层，由 CLI 的 `--divisor` / `--top-n` 决定，只作为审计元数据记入 `bt_run.universe_params_json`。改它们等于改池子，不是「调策略参数」。

- `wufu-rotation` **必须配 `--universe dynamic`**；固定池面板里没有动态池候选。
- `--indexes` 只在 `--universe dynamic` 下生效；wufu 不传时默认为四个走弱期指数。
- `--price` 默认 `open`；`--benchmark` 默认 `sh510300`；`--db` 缺省按 `BACKTEST_DB_PATH` / 业务库同目录解析（本地开发为 `data/backtest.db`），`--no-db` 不落库。
- 工作日 **17:00–17:10（Asia/Shanghai）** 是行情写入与纸面日更窗口，禁止跑 `run` / `sweep`；确有补跑需要时，人工确认后设 `BACKTEST_WRITE_WINDOW_GUARD=off`。
- DuckDB 行情层只读；回测结果写独立回测库（默认 `data/backtest.db`，可用 `BACKTEST_DB_PATH` 覆盖），不写业务库。

## 9. 纸面账户与回测的差别

- 纸面白名单登记 `(wufu-rotation, 5.2.0-m3)`；账户按 `(strategy_id, strategy_version)` **精确匹配**，不做「同 id 取最新版本」的隐式升级。
- 纸面在行情更新到 `T` 后决策，订单指向 `T+1`；影子期落 `paper_order(status='shadow')`，**不写** `paper_position` / `paper_equity`，持仓恒空。
- **策略内部状态不持久化**：每次决策把 `[start_date .. T]` 重放一遍，重建走弱期与 `lastPool`；中间日使用空组合，最终日才用检查点组合。
- wufu 的跨日状态（`weak` / `startDayIndex` / `lastPool`）只依赖行情与池子，不依赖持仓，因此可以被回放重建；但中间日的止损 / 持仓保留判断用的是空组合，最终日才看到真实持仓。
- 影子期不结算、不产生成交、不调 `onFill`。因此**纸面结果不得与回测结果互相校验**；纸面只用于验收「能选中该策略、能读到参数 schema、能按当日上下文出一次决策」。回测才是唯一有效验收入口。

## 10. 已知偏差与限制

| 编号 | 项 | v5.2 | MVP | 影响 |
|---|---|---|---|---|
| B1 | 决策时点 | 13:10 `last_price` | T-1 收盘决策 + T 开盘成交 | 无前视；路径等效度约 88–92%；13:10 价与收盘价偏差代理均值 0.766%，单只 score 变动通常 <2%（估算），足以在临界名次翻转 |
| B2 | 成交量 | 13:10 分时量投影到全日 | 全日成交量 | 量比低估约 10–20%（估算），偏宽松；建议输出量比 ×0.85 / ×1.0 敏感性 |
| B3 | 止损 | 分钟级每 bar 检查 + 立即市价卖 | 决策时 `asOf` 收盘判定 + T 开盘卖出 | 低估回撤；年化影响约 0.3–1%（估算）；可给「无止损 / 收盘止损」区间 |
| B4 | 盘中临时停牌 | 10 分钟无成交视为停牌 | 不实现 | 极少数日误买/误卖；影响 <0.5%（估算） |
| B5 | 涨跌停 / 停牌 | `high_limit/low_limit` 字段 | `preclose × (1±10%)`；停牌 = 缺 bar ∪ 零量 | 科创 / 创业 ETF 实际 20% 档，可能把正常波动误判为涨跌停；停牌为推断口径 |
| B6 | 防御仓位 | 首次进防御吃满可用现金，之后不再调整 | 同 v5.2 | 不是每日按权益再平衡；`targetWeight=1` 只是决策留痕，实际金额由 `remaining-cash-equal` 决定 |

其他限制：

- **固定池是事后选池**：只能从 2023 年起做样本；长样本用时点池并分段，禁止给单一全样本年化。
- **名称是当前快照**：动态池分组存在轻度前视；15.4% 名称末字损坏、24.3% 标的无名称（多为停更残段），分组键取前 2 字以降低影响。
- **有效点不足默认淘汰**：`expandLookback=true` 是显式偏离，停牌密集标的会算出原版算不出的分数；默认关闭并在标签里记录影响面。
- **N>1 的候选顺序**：MVP 始终按 score 降序；v5.2 在保留数不足时保留原持仓顺序。只影响下单先后，N=1 默认配置下完全一致。
- **数据范围**：可行性报告的实测截止 2026-10-12；跑之前以 DuckDB 库内最新交易日为准，并在结论里标注区间。
- **没有分钟/tick 数据**：不实现盘中实时信号、分钟止损、13:10 真实成交价；与项目 Out-of-Scope 一致。
- **没有生产信号侧**：目前只有回测 CLI 与纸面影子决策，没有 API / UI / 推送。

### 12.3 常见误解

1. **「五福 = 固定持有五只 ETF」**：不是。默认 `holdingsNum=1`，全仓单只；「五福」是策略名称。
2. **「固定池 114 只是当前持仓 / 当前候选」**：不是。它是静态候选池，还要过流动性、打分、过滤，最终默认只买 1 只。
3. **「持续走弱 20 天后会强制退出」**：不会。进入条件仍成立时每天重置计数，20 日强退实际不触发；这是 v5.2 现状，不要当 bug 修。
4. **「R² 是标准加权 R²」**：不是。残差与总平方和都加权，但总平方和的中心是无权均值；混合口径已锁进 golden。
5. **「防御 ETF 每天再平衡到 100%」**：不是。100% 指首次进防御时吃满可用现金，之后 `hold` 不再调整。
6. **「divisor / topN 是策略参数」**：不是。它们属于 universe 层；改它们等于改池子，不是调策略。
7. **「纸面结果可以校验回测」**：不可以。纸面影子期不结算、不产生成交，只用于验收决策链路。
8. **「固定池 114 只可以回溯 2015」**：不可以。它是按 2026 年时点选的事后名单，32 只 2023 年后才上市；长样本用时点池。
9. **「sh510300 / sh511880 / 四个指数是一回事」**：不是。`sh510300` 是回测基准，`sh511880` 是防御 ETF，四个指数（`sh000300` / `sz399101` / `sz399006` / `sh000510`）只用于走弱期投票。

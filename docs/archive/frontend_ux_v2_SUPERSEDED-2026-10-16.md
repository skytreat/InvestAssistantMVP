# InvestAssistant MVP 前端 UX/UI 审查报告 v2

**审查日期**：2026-10-16
**审查基准**：`docs/client/PRD.md §5 交互与体验要求`、`apps/frontend/src/` 全部源代码
**审查范围**：信息架构、视觉设计系统、逐页 UX、微交互、可访问性、响应式、渐进式增强
**审查方式**：源代码静态分析 + 浏览器快照（7 个页面，1187x914 视口）

---

## 0. 执行摘要

当前 MVP 前端处于**"功能可用但体验粗糙"**的阶段。核心代码路径全部基于内联 JSX style 对象（无 CSS 层），视觉系统缺乏设计 token、无暗色模式、无响应式断点。7 个页面共 14 个内联颜色值，其中 6 个是同一蓝色的不同深浅但命名不一致。

与 PRD §5 相比，**P0 级差距集中在**：
- Dashboard 缺少资产汇总卡片和持仓卡片化布局
- TradeInput 缺少 Tab 切换、实时预估、快捷标签
- Kline 缺少十字光标、信号标记、动态参数面板
- Review 缺少双口径切换、收益曲线、筛选增强
- StockScan 参数输入为裸 JSON textarea 而非动态表单
- Admin 缺少校验仪表盘卡片、日志过滤、备份恢复

**好消息是**：基础导航结构正确、7 种交易类型都可录入、持仓表能正确显示、Signals 页面方向颜色正确、Review 的编辑弹窗工作正常。说明**后端接口能力已就绪，前端 UX 层可独立迭代**，不会阻塞后端。

## 1. 信息架构

### 1.1 当前导航结构

```
[Logo] InvestAssistant | 仪表盘 | 交易录入 | 策略信号 | K线图 | 条件选股 | 交易复盘 | [管理员] | admin (管理员) | [退出登录]
```

- 导航条为顶栏横向排列，所有页面共享同一 Navbar 组件（`_shared.tsx`）
- 管理员链接仅 `role === 'admin'` 时显示
- 导航项使用 React Router `Link` 无刷新切换
- **当前页高亮无视觉区分**：所有 Link 使用同一 `linkStyle`，无 `:active` 状态、无背景色、无下划线

### 1.2 与 PRD §5.8 差距

| PRD 要求 | 当前状态 | 差距级别 |
|----------|---------|---------|
| 桌面端左侧导航栏 | 顶部水平导航 | P1 |
| 移动端底部 Tab 栏 | 无响应式 | P1 |
| 候选池页面 | 完全缺失（当前 StockScan 结果无"加入候选池"操作） | P0 |
| 设置页面 | 缺失 | P2 |

### 1.3 建议

**问题 1-1：当前页无高亮状态**
- **当前状态**：`linkStyle`（`#1e40af` 蓝色、padding `8px 12px`、borderRadius 4px）对所有导航项一视同仁
- **问题**：用户不知道自己在哪个页面，也不知道点击哪个会去哪里（尤其是导航链接多时）
- **建议方案**：引入 NavLink 组件 + active 态样式。使用 `react-router-dom` 的 `NavLink`，active 时设置 `background: #eff6ff`（浅蓝底）+ `color: #1d4ed8`（深蓝字）+ `fontWeight: 600`
- **优先级**：P0（低成本高收益）
- **工作量估算**：0.5 人天（替换 `<Link>` 为 `<NavLink>`，新增 active 样式常量）

**问题 1-2：缺少导航分组逻辑**
- **当前状态**：7 个导航项平铺
- **问题**：仪表盘→交易录入→策略信号→K线图→条件选股→交易复盘→管理员，业务流程链是"记交易→看持仓→跑策略→看K线→选股→复盘"，但导航顺序被打散了（K线图在信号之后，选股在复盘之前）
- **建议方案**：重新排列为 **仪表盘（首屏）→ 交易录入（高频入口）→ 条件选股（前端）→ K线图（深度分析）→ 策略信号（结果查看）→ 交易复盘（周期任务）→ 管理员（运维低频）**
- **优先级**：P2
- **工作量估算**：0.2 人天

**问题 1-3：缺少面包屑和页面标题层级**
- **当前状态**：Dashboard/TradeInput/Review/Admin/Signals 使用 `<h1>`；Kline/StockScan 用 `<h2>`
- **问题**：H 级不一致（部分页面 h1、部分 h2）；Navbar 有"InvestAssistant"大标题，页面内又有 h1，视觉层级模糊
- **建议方案**：统一使用 h2 作为页面主标题（与 Navbar 的 InvestAssistant brand 字重区分），所有页面保持一致

### 2.3 一致性问题清单

**问题 2-1：输入框圆角 4px vs Card 圆角 8px**
- 所有 input 使用 `borderRadius: 4px`
- 所有 Card 使用 `borderRadius: 8px`
- 表格 border 也用 `4px`？不，thTdStyle 没有定义 borderRadius（0）
- **建议**：统一为 `6px`（Material Design、Ant Design 等主流组件库的平衡值），或设 `INPUT_RADIUS = 6`、`CARD_RADIUS = 10` 形成层级差

**问题 2-2：表格无斑马纹、无 hover 态**
- 当前表格行纯白底、无边框高亮、无悬停效果
- Review 和 Dashboard 表格视觉上像"纯数据块"，缺乏可读性
- **建议**：新增 `TABLE_ROW_HOVER = '#f1f5f9'`、`TABLE_ROW_STRIPE = '#fafbfc'`，在 `tr` 的 inline style 中加入

**问题 2-3：按钮仅有 Primary 变体**
- `buttonStyle` 是蓝色 `#2563eb`
- Review 有红色删除按钮（inline `background: #dc2626`）
- 没有 Secondary（灰色）、Ghost（透明）、Link（仅文字）变体
- **建议**：在 `_shared.tsx` 导出 `dangerButtonStyle: { background: '#dc2626', color: '#fff' }`、`ghostButtonStyle: { background: 'transparent', color: '#2563eb', border: '1px solid #2563eb' }`、`secondaryButtonStyle: { background: '#e5e7eb', color: '#374151' }`

**问题 2-4：没有 Focus 样式**
- 全局没有 `:focus-visible` 的替代样式
- 键盘 Tab 导航后，聚焦元素无视觉反馈
- **建议**：在 `_shared.tsx` 导出 `focusRingStyle: { outline: '2px solid #2563eb', outlineOffset: '2px' }`，在所有可聚焦元素的 style prop 中添加

**问题 2-5：删除按钮视觉层级过高**
- Review 的删除按钮在表格行内、红色、与编辑复盘按钮平级
- 高危操作不应与常规操作平级
- **建议**：删除按钮改为 Ghost 样式 `background: transparent; color: #dc2626; border: 1px solid #dc2626;`，或改为行尾的"..."更多菜单

**优先级**：问题 2-1 ~ 2-4 全部为 P1，问题 2-5 为 P1。整体视觉一致性改造估算 1.5 人天。

## 3. 逐页面 UX 审计

### 3.1 Dashboard（仪表盘）

**PRD 基准**：§5.3 持仓页交互 + §5.8 全局体验要求

#### 当前状态快照

仪表盘包含三个卡片：持仓汇总表、最新信号表（仅管理员：最近日志表）。页面结构为 h1 "仪表盘" → card1 持仓 → card2 信号 → card3 日志。

#### 问题清单

**问题 3-1-1：缺少资产汇总卡片（总资产/总盈亏/总收益率）**
- **PRD 要求**：§5.3 明确"顶部大卡片：总资产、总盈亏、总收益率（颜色区分正负）、双口径切换"
- **当前状态**：完全缺失。持仓汇总表直接展示具体持仓列表，无任何汇总统计
- **建议方案**：在持仓表格上方新增一张全宽资产卡片，包含：
  ```
  +--------------------------------------------------+
  |  [实际收益率]  [价格收益率]   ← Tab 切换          |
  |                                                  |
  |  总资产          总盈亏(+5,230.00)     总收益率    |
  |  ¥ 105,230.00    +5.23%               +5.23%      |
  |                                                  |
  |  持仓 3 只  |  股票 ¥80,000  |  ETF ¥25,230     |
  +--------------------------------------------------+
  ```
  - Tab 切换对应"价格收益率 vs 实际收益率"双口径
  - 正数绿色 #16a34a、负数红色 #dc2626
  - 标签小号字体 #6b7280，数值大号粗体
- **优先级**：P0
- **工作量估算**：0.8 人天（后端需要补 positions/summary API，前端做 Tab 切换 + 统计数据渲染）

**问题 3-1-2：持仓表应改为卡片化布局**
- **PRD 要求**：§5.3 "持仓卡片列表，每只标的：代码+名称、现价、持仓数量、移动加权成本、盈亏、收益率、仓位占比（进度条）"
- **当前状态**：纯表格 `<table>` 展示，只列了 4 列（股票代码/数量/均价/已实现盈亏）
- **差距**：
  - 缺少"现价"列 → 无法计算浮动盈亏
  - 缺少"盈亏金额"和"收益率" → 无法一眼看到赚钱/亏钱
  - 缺少"仓位占比"进度条 → 无法判断哪只持仓最大
  - 缺少标的中文名称（只有代码）
  - 缺少快速操作按钮（PRD §5.3 要求【买入】【卖出】快捷按钮）
- **建议方案**：改为响应式网格卡片
  ```
  +-----------------------+  +-----------------------+
  | sh600519              |  | sh600000              |
  | 贵州茅台              |  | 浦发银行              |
  | 现价 ¥1750.00         |  | 现价 ¥10.23           |
  | 持仓 100 股           |  | 持仓 1000 股          |
  | 成本 ¥1730.50         |  | 成本 ¥10.00           |
  | 盈亏 +¥1,950 (+1.12%) |  | 盈亏 +¥230 (+2.30%)   |
  | ▓▓▓▓▓▓▓▓▓▓ 28.5%      |  | ▓▓▓▓▓ 12.3%           |
  | [+买入] [-卖出]       |  | [+买入] [-卖出]       |
  +-----------------------+  +-----------------------+
  ```
  - 桌面端 3 列，平板 2 列，手机 1 列
  - 每卡片底部：仓位占比进度条 + 快速操作按钮
- **优先级**：P0
- **工作量估算**：2.0 人天（后端补 positions enrich API 返回现价+浮动盈亏，前端卡片组件+响应式网格）

**问题 3-1-3：缺少资产组成饼图**
- **PRD 要求**：§5.3 "资产组成饼图，股票+ETF 按市值分布"
- **当前状态**：完全缺失
- **建议方案**：在资产汇总卡片右侧或下方增加简化饼图（可用纯 SVG 手写，无需引入 chart 库）
- **优先级**：P1
- **工作量估算**：1.0 人天

**问题 3-1-4：最新信号表格无内容时应引导用户**
- **当前状态**：信号为空时显示"暂无信号"
- **问题**：无法区分"今日还没跑信号"vs"跑了但确实没有"vs"插件引擎没配置"
- **建议方案**：
  - 空状态文字改为"今日暂无策略信号"
  - 附一行浅色小字提示"收盘后 17:03 自动运行信号生成"
  - 管理员角色额外显示【立即运行信号】按钮（跳转到 Admin 页）
- **优先级**：P2
- **工作量估算**：0.3 人天

**问题 3-1-5：Dashboard 页面整体过载**
- **当前状态**：持仓 + 信号 + 日志三张"纯表格卡片"堆叠
- **问题**：首页应该是"概览 + 快速入口"，而不是把所有数据塞进来
- **建议方案**：Dashboard 重新定位为"概览页"，三张卡片改为：
  1. 资产汇总卡片（核心）
  2. 今日快捷操作区（今日买入、今日卖出、查看全部交易入口）
  3. 持仓 Top 3 卡片（快速概览）
  4. 策略信号 Top 5
  - 信号详情页面化（Signals 页面承担更多信号筛选/分析功能）
- **优先级**：P1
- **工作量估算**：1.5 人天

#### 3.1.A Dashboard 工作流统一优化（用户视角建议，3 个连贯的交互增强）

> 以下 3 条建议来自产品使用场景分析——核心思想是**把高频操作和核心信息压缩在 Dashboard 一个页面内，减少不必要的路由跳转**。三条建议独立可做，但一起实施能形成完整的 Dashboard 交互闭环。

##### 建议 A：持仓卡片直接展示策略信号状态（避免跳页）

- **当前问题**：用户想看持仓的策略信号，必须跳去独立的 Signals 页面或 Kline 页面，在 10+ 只持仓里逐一找
- **PRD 对齐**：§M3 "K 线图上看到策略信号标记"——K 线有了，持仓作为更快的概览入口是合理延伸
- **建议方案**：每张持仓卡片右侧（或名称下方）直接显示当前策略信号状态，用**极简图标**：
  ```
  +-----------------------+
  | sh600519 贵州茅台     |  ← 名称（可点击触发建议 C 的详情弹窗）
  | [▲买入]  RSI 32 超卖   |  ← 信号标记（绿▲=买入/红▼=卖出/灰·=持有）
  | 现价 ¥1750.00         |
  | 盈亏 +¥1,950 (+1.12%) |
  | ▓▓▓▓▓▓▓▓▓▓ 28.5%      |
  | [+买入] [-卖出]       |
  +-----------------------+
  ```
  - 无信号时显示 `·持有`（灰色小点）
  - 信号过期（超过 5 个交易日未更新）显示 `⚠信号过期`（橙色三角）
  - **后端实现**：持仓列表 `GET /api/trades/positions` 返回时，批量 `IN (...)` 查询信号表，一次返回所有持仓的最新信号（避免 N+1）
- **优先级**：**P0**（与问题 3-1-2 持仓卡片化一起做）
- **工作量估算**：0.5 人天（后端补 enrich + 前端渲染图标）

##### 建议 B：交易录入改为模态对话框（避免整页跳转）

- **当前问题**：用户在 Dashboard 看到持仓想操作，点击"买入/卖出"后跳去独立的 `/trade` 页面，填完表单后还要手动返回 Dashboard
- **PRD 对齐**：**§5.4 标题就是"交易录入弹窗"**——PRD 的用户旅程是"持仓卡片 → 快捷按钮 → 弹窗"，当前实现偏离了这个设计意图
- **建议方案**：保留 `/trade` 路由作为"快速录入页面"（支持无持仓时直接录入），但 Dashboard 持仓卡片和 Review 交易编辑的"买入/卖出"按钮**触发 Modal**：

  +--------------------------------------------------+

  |  价格      [ 1750.00 ] ¥/股                       |
  |  手续费    [    0.00 ] ¥                        |
  |                                                  |
  |  ┌─ 预估 ──────────────────────────┐             |
  |  │ 新均价    ¥1730.50             │             |  ← 实时预估（PRD §5.4）
  |  │ 总投入    ¥175,050.00          │             |
  |  │ 手续费计入  ¥0.00               │             |

  - 预估面板**实时计算**：用户改数量/价格/手续费时即时更新新均价
  - Tab 切换时**字段联动**：买入→显示预估，清仓→自动填持仓数量并置灰

- **工作量估算**：1.0 人天（抽离 Form 组件 + Modal 外壳 + 联动逻辑）

## 5. 可访问性（Accessibility / a11y）

### 5.1 当前问题

| 方面 | 状态 | 问题 | 修复建议 |
|------|------|------|---------|
| **键盘 Tab 导航** | 可用 | 顺序依赖 DOM 顺序，无 tabIndex 管理 | 确保 focus 顺序合理（从左到右、从上到下），Modal 打开后 focus 锁定在 Modal 内 |
| **Focus 样式** | 完全缺失 | 键盘用户看不到当前聚焦哪个元素 | 全局 `:focus-visible` 替代样式（见 §2.3 问题 2-4） |
| **表单 label 关联** | 部分缺失 | TradeInput 的 SymbolAutocomplete input 没有 `<label htmlFor="...">`；Review 筛选 select 用了 `<label>` 但没 for 属性 | 所有可聚焦 input/select 必须有关联的 label |
| **表格 scope** | 缺失 | `<th>` 没有 `scope="col"` 或 `scope="row"` | 表头加 `scope="col"`，行头（如有）加 `scope="row"` |
| **按钮 aria-label** | 缺失 | 纯图标按钮不存在（当前都是文字按钮，问题不大），但"退出登录"应有 `aria-label="退出当前用户 admin 的登录状态"` | 高危/模糊按钮补充 aria-label |
| **颜色对比度** | 部分不足 | - 红 `#dc2626` 背景 + 白字的按钮对比度满足 WCAG AA（4.5:1）；- 但 `#16a34a`（盈利绿）作为背景色时，白字对比度刚好达标（4.5:1 临界）；- `#6b7280`（浅灰文字）在白色背景上对比度约 4.6:1，刚好达标 | 建议升级到更深的语义色：红 `#c81e1e`，绿 `#15803d`，灰 `#4b5563` |
| **语义化 HTML** | 部分缺失 | 页面容器用 `<div>`，没有 `<main>` 标签；Navbar 用 `<div>`，没有 `<header role="navigation">` | 引入语义化标签：`<header>`、`<main>`、`<nav>`、`<section>`、`<footer>` |
| **aria-live** | 缺失 | 实时更新的 Dashboard、K 线图、加载状态变化无 aria-live 区域 | 关键动态内容区域加 `aria-live="polite"` |
| **合规声明** | 完全缺失 | PRD §5.8 第 4 条 + §5.9 要求"本工具不构成投资建议，数据仅供参考"常驻 | 全局 footer 常驻一行声明 |

### 5.2 建议的 a11y 修复优先级

- **P0**：Focus 样式 + 合规声明常驻
- **P1**：表格 scope + 表单 label 关联 + 语义化 HTML
- **P2**：aria-live + 颜色升级

整体估算：2.0 人天

## 6. 移动端 / 响应式

### 6.1 当前状态

**完全没有响应式设计**。具体表现：

### 6.3 响应式改造优先级建议

移动端适配的工作量是**所有 UX 改进中最大的**，需要谨慎规划。

- Navbar 在 < 768px 时折叠为 hamburger menu

**Phase 3（P2，体验优化）**：
- touch-friendly 的按钮尺寸（≥ 44×44px 点击区域）
- 下拉选择器改为原生 `<select>`（已做 OK）
- 手势支持（K 线图左右滑动查看历史）

**整体估算**：3.0 人天（Phase 1）+ 5.0 人天（Phase 2）+ 2.0 人天（Phase 3）

### 8.3 关键架构决策建议

1. **当前 inline style 方案可以保留**，但必须引入 Token 常量层。不要急于切换到 CSS Module 或 Tailwind，在 MVP 阶段保持简单。

2. **建议引入一个轻量 CSS 文件**（如 `global.css`）来定义全局 `:focus-visible`、`body` 背景色、`html`/`body` margin 重置等，这些用 inline style 很难优雅表达。

3. **图表库暂不引入**，当前 Canvas 手写方案继续用。PRD 要求 K 线图有十字光标、信号标记、MA 开关、参数实时调节，纯 Canvas 完全可以实现。引入 ECharts 或 TradingView 会增加依赖体积，且自定义深度不够（尤其信号标记在 TradingView 中受限）。

4. **TradeInput 的实时预估算法**应在前端本地实现（移动加权成本公式不复杂），这样不用每次都打 API，响应即时。同时这套前端算法和后端 golden dataset 的一致性需在 CI 中验证（AGENTS.md 已有此要求）。

5. **Dark mode 推迟**（PRD 标为"MVP 可选"）。

## 2. Tier 判据（本方案的解释）

### 2.1 证据优先级（ADR 原文，R2）

`代码产物` > `可执行证据（相关测试现通过）` > `审计记录` > `计划勾选`。

**推论**：计划勾选（`✅ 完成` / `⬜ 待启动`）**只能作为「去哪里找证据」的线索**，不能作为 PASS 依据。任何一条核验记录，若其最高证据等级只有「计划勾选」，必须判 **NOT VERIFIABLE**，不得判 PASS。

### 2.2 分层判据（本方案解释）

**判据 = 风险暴露面 × 证据可获得性，而不是验证成本。** 理由：D2 原文三层的列举标准是「对象性质」（未关闭 / 最近完成 / 历史关闭）与「证据强度」（实测 / 产物存在 / 文档），成本只是结果，不是分级原因。

| 层 | 进入条件（满足任一） | 证据最低要求 | 结论效力 |
|---|---|---|---|
| **A 必须实测** | ① 状态非 ✅（⬜ / 🟡）；② 属于 §13 开放偏差；③ 数据正确性 / 安全门槛项；④ 被 V3 计划**显式**引用 | 代码产物 + 可执行证据（定向测试或命令实测） | 可判 PASS / FAIL；证据不足判 NOT VERIFIABLE |
| **B 只查产物存在性** | ⑤ 最近完成（Wave 9–12）；⑥ 契约被 V3 消费但未被显式列为前置 | 代码产物存在性（文件 / 导出符号 / DDL / 路由）+ 审计记录引用 | 可判 PASS（产物存在）/ FAIL（产物缺失）/ NOT VERIFIABLE（路径不可判） |
| **C 仅文档确认** | ⑦ 已 `✅ 完成` 且 `docs/audit/wave-N-audit.md` 判定 PASS 的历史任务 | 审计记录（文档） | 只允许判「文档确认 PASS（冻结时未复跑）」；**不得表述为「已验证」** |

**互斥规则**：满足 Tier A 条件的**一律进 A**，即使它同时「最近完成」（A 优先，取最强证据要求）。

$f='docs\client\code_implementation_plan_v2.md'
$labels=@(); $i=0
Get-Content $f | ForEach-Object {
  $i++
  if($i -ge 225 -and $i -le 427 -and $_ -match '^\|'){
    $c=$_ -split '\|'
    if($c.Count -ge 4 -and $c[1] -match 'T\d+[ab]?c?'){ $labels += (($c[1] -replace '[^\w]','')) }

"rows=$($labels.Count)"; "unique=$(($labels | Sort-Object -Unique).Count)"

## 4. 抽样方案

### 4.1 必须全量（不抽样）

- **Tier A 全部**：9 个未关闭任务 + 17 条开放偏差 + 6 条数据正确性项 + 2 个 V3 显式依赖（去重后约 30–34 项）。
- **Tier C 全部**（**D4 已决策：全量**；单条约 3–5 分钟，全量约 1.5–2.5 h，见 §7）。

### 4.2 可抽样范围（仅限 Tier B）

- Tier B 中「产物存在性」检查：若对象 > 20 个，可抽 50%，但**必须分层**：每个 Wave 至少抽 1 个，且 Wave 12（无审计）**不得抽样，必须全查**。
- **Tier A / Tier C 一律不抽样**（D4 已决策；避免与 §4.1 自相矛盾）。

### 4.3 选样规则（仅适用于 Tier B；禁止「挑好核的」）

1. **先冻结名单再抽**：把 67 个唯一任务标签排序后写入核验记录（`INVENTORY` 表），抽样在名单冻结后执行。
2. **随机源可复现**：`Get-Random -SetSeed <记录在案的种子>`，种子写入核验记录元信息。
3. **分层强制**：Wave 1–12 各至少 1 个；缺审计的 Wave（当前 = Wave 12）全量。
4. **置信度表述纪律**：Tier B 抽样时**不声称「95% 置信」**（样本量与总体比例不支持二项置信区间的强表述）。本方案只声称「抽样覆盖」，并在结论中写明未抽样项 = `NOT VERIFIED`。
5. 结论区分三档：`PASS`（已核）/ `NOT VERIFIED`（未核/未抽到）/ `FAIL`。**禁止把「未抽到」写成 PASS。**

## 8. 风险与红线

### 8.1 核验过程中的风险与规避

| 风险 | 触发场景 | 规避 |
|---|---|---|
| DuckDB 文件锁 | 同一进程内重复 open 未 close，或未来恢复增量更新后与 tdx2db 并发 | 每次查询 `finally` 关闭；失败即标 NOT VERIFIABLE，**不重试刷屏**（本机当前无 tdx2db 争锁，§3.4） |
| 污染工作区 | 跑测试生成 `data/*.db`；误用 `git stash` | 起跑前后 `git status --porcelain` 对比；测试一律 `:memory:`；不改 tracked 文件 |
| 全量测试卡死 | 直接 `npm test` | 只跑定向子集（§5） |
| `EADDRINUSE` | 并行起多个 Fastify 实例 | 串行；遵循 `singleFork=true` |
| Windows PowerShell 编码/转义坑 | 中文输出乱码、JSON 内联被吞 | 需要复杂参数时写临时 `.js` 脚本再 `node` 执行（本仓既有做法） |
| 误把审计记录当结论 | 只读 `wave-N-audit.md` 就判 PASS | Tier C 只能标「文档确认未复跑」；Tier A 必须有代码产物或可执行证据 |

### 8.2 红线（本轮与开跑后同样适用）

1. **不改 `plan_v2`**：不打 `frozen` 头、不改 §13、不动正文（ADR L44）。
2. **不建 `docs/tasks/v2/`**（本轮明确不建）。
3. **不改业务代码与测试**：核验只读；发现缺陷只**记录**，不顺手修（AGENTS.md「sub-agent 只许报告疑点」同理）。
4. **不提交、不推送**本方案以外的任何文件。

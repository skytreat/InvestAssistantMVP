## 4. 变化幅度与判读

| 指标 | 变化幅度 | 判读 |
|---|---|---|
| M1 | **−45.7%**（字节）/ ≈−46%（token 估算） | 确定性，可直接作为「常驻上下文成本减半」的证据 |
| M4（a1 vs b2） | **−6%**（8.9 vs 9.5 min） | 方向为「略快」，但幅度**小于 before 内部离散（−41%）** ⇒ **不可作为效应量** |
| M4（a1 vs b1） | −44%（8.9 vs 16 min） | 同样被噪声吞没 ⇒ 不引用 |
| M4（a2） | +46.9 min（含 35 min 测试卡死） | **失真**，只作上界，不参与对比 |
| 交付物规模 | ±0（367–467 行区间重叠） | 质量量级持平 |
| M2 / M3 / M5 | **无数据** | 无法给幅度 |

**核心判读**：before 两次跑在同一提交族、同一 brief、同一模型下就有 **16 vs 9.5 min（−41%）** 的离散，
说明 M4 的**噪声底大于可能的文档效应**。因此：
1. 任何基于单次 M4 的「优化提速 X%」结论都应拒绝；
2. 唯一诚实的表述是「**M4 未见恶化**」；
3. 要测真实的「省 token / 少读文件」，必须换到能导出 M2/M3 的 harness。

## 5. 结论

1. **H1 部分成立**：ADR-018 §6 把常驻提示体量减半（**−45.7%**），并让文档结构**可机器校验**（`docs-lint` 0 ERROR/0 WARNING），开放项不再靠人肉记忆。
2. **H1 的「读得更少 / token 更省」未获测量支撑**：M2/M3/M5 在 IDE 内 Trae 侧均不可采，**记为 NOT COLLECTED，不外推为「已验证」**。
3. **质量侧无回归证据**：四组交付物规模同量级（367–467 行 / 5 文件）；但 M5 未判读 ⇒ 「质量不降」同样**只是未观测到下降**，不是已证明不降。
4. **流程副产物有价值**：本次实验暴露了 3 条无效样本（流中断 / 并发污染 / 关机中断），直接验证了「串行单 agent + 干净树 + 完整收尾」三条纪律的必要性（baseline §7.3）。

## 6. 局限

| # | 局限 | 影响 |
|---|---|---|
| L1 | **M2/M3 不可得**（IDE 内 Trae 无工具调用流水、不暴露 token） | H1 的核心子命题**未验证**；`M1` 只是**代理指标**（常驻文本 ≠ 实际读取量） |
| L2 | **M5 未判读**（未跑 `bench-probe`） | 「遗漏规格不上升」无客观分数，仅 agent 自报测试通过（未经复核） |
| L3 | **M4 噪声大**（before 内部 −41% 离散；a2 含 35 min 测试卡死） | 耗时差异**不可归因**于文档优化，只能表述「未恶化」 |
| L4 | **工具口径不可混用** | Trae（`DeepSeek-V4.1-Flash`）与 opencode（`agnes-3.0-flash`）的 M2/M3/M4 采集机制不同，**跨工具比较无效**；opencode 的 b1/b2 数据（baseline §7/§7.1）**仅作附注，不参与主对比** |
| L5 | **N=2 且未配对**（每次跑独立，非同一任务重复测量） | 无法给置信区间；只可作方向性描述 |
| L6 | **after 侧提示效应**：a 组能看到新增的 `docs/INDEX.md` 与 D 卡，检索路径被结构引导 | 这正是自变量，但意味着**不能把差异全归因于 AGENTS 瘦身** |
| L7 | **总字节未减**（playbook 19.7KB 抵消 AGENTS 节省） | 若 agent 频繁命中 playbook，净上下文成本可能**不降反升**；本实验无法证伪 |

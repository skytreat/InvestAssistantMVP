### 5.1 ⚠️ C11/C12 阈值冲突（**已裁决 C**，下表为裁决前状态快照）

> 📌 **以下表格记录的是「发现时的四方冲突」，属审计证据，数值已过时**。
> **现行口径见下方「✅ 裁决结果」。** SDD 那一行是初版 I-8 错误应用后的中间态。

| 来源 | C11 失败级别 | C12 失败级别 | 当时的权威性 |
|---|---|---|---|
| **Requirements §7.3** | >3 → WARN；**>5 → ERROR** | >5 → WARN；**>1 只差异>0.1 元 → ERROR** | B-14 说它权威 |
| **PRD §6.2** | ≤3/30 差异 | ≤5/20 差异 | I-8 说它权威 |
| **SDD §5.7**（初版 I-8 后）| ≤3 → WARN，**>3 → ERROR** ❌ | ≤5 → WARN，**>5 → ERROR** ❌ | **该结果已被裁决 C 推翻** |
| **代码实测** | **≤2 → WARN，>2 → ERROR** | **≤2 → WARN，>2 → ERROR** | 🔴 **谁都不符** |

**根因**：**B-14 裁决只覆盖了 C1-C10**（ADR-004 修订记录原文：「整体重写为以 Requirements §7.1 为准」），
C11/C12 走的是**另一条裁决 I-8「以 PRD 为准」**，而**该裁决从未进 ADR-004 修订记录** ——
即「以 PRD 为准」这个决定**没有落档**，导致无法判断该信谁的。

**影响面**：T97（执行参数）的测试断言直接依赖此阈值；G1 gate 的 C11/C12 用例无法编写。

**建议裁决方向**（待所有者拍板）：
- **A. 以 Requirements 为准** → C11 ERROR 门槛 `>5`、C12 ERROR 门槛 `>1 只差异>0.1 元`。与 B-14 一致，但 C12 ERROR 极严（20 只里 2 只差异就 ERROR）
- **B. 以 PRD 为准** → C11/C12 均 `>3` / `>5` → ERROR。与 I-8 一致，但与 B-14「C1-C12 以 Requirements 为准」冲突，**B-14 需加限定词「C1-C10」**
- **C. 重新定义** → 认为 PRD §6.2 写的是**匹配率目标**（业务期望），Requirements §7.3 写的是**告警策略**（技术分级），二者不冲突，是两个维度 → 需在 Requirements §7.3 补注区分

> 我的倾向是 **C** —— PRD §6.2 那两行的表头是「C11 跨源原始数据**匹配率**」，属成功率指标；
> Requirements §7.3 的列是「**失败级别**」，属告警分级。它们本就是两件事，被 I-8 当成同一件事裁决了。
> **但这需要你确认，我不替你决定。**

### 5.2 ⚠️ SDD 行情层字段名大面积失实（本次实测发现）

`docs/tdx2db_schema_dump.sql` 是 tdx2db 实际写入的结构。逐表核对 SDD §3.3 / §5.2 时序图后发现：

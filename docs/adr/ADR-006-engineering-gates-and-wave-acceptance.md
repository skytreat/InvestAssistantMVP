## 背景

SDD §12.2 定义了分模块覆盖率目标，并要求「核心算法层 + 插件引擎 < 90% **阻断合入**」；
§12.6 CI Stage 2 定义了「Lint + TypeScript Check」并把「Lint 失败」列为阻断点。

实测仓库状态：

| 项 | SDD 要求 | 实际 |
|---|---|---|
| 覆盖率 Gate | 核心 ≥90% 硬 Gate | `ci.yml` 只有 `--coverage` 上传 artifact，**无任何 threshold 断言** |
| 前端测试 | 前端 ≥70% | **0 测试**（无 vitest / jsdom / testing-library） |
| ESLint | CI Stage 2 阻断 | **无 `.eslintrc*` / `eslint.config.js`**，根 `package.json` **无 `lint` 脚本** |
| Prettier | 格式化统一 | **无 `.prettierrc`** |

矛盾点：实施计划 §12.4 E6「`any` 降到 0」与 T66「`any` 清零」**都以「需先配 ESLint」为前提**，
但**没有任何任务负责配 ESLint**。

## 决策

### 1. 覆盖率门槛：**暂维持下调，后续由 T86b 补回**（B-5）

SDD §12.2 的目标数值**保留不动**（SDD 是目标态），但显式标注当前冻结：

| 模块 | SDD 目标 | 过渡期实际执行 |
|---|---|---|
| 前端 | ≥70% | **≥60%**（当前 0） |
| backend | 各模块分档 | **不低于当前基线**（暂不设硬门槛） |
| CI 90% Gate | 阻断 | **冻结** |

**理由**：前端 0 测试、无测试基建的情况下设 90% 硬 Gate 会让 CI 从第一天起就红，
并诱导为凑数字写无意义测试。

**恢复义务**：**T86b（Wave 8）** —— 测试存量到位后**必须把 SDD §12.2 数值与 90% CI Gate 恢复**。
在此之前 §12.6 的全局判定**不因覆盖率判 FAIL**。

> 本条为**暂缓**而非取消。

### 2. 补 Wave 2 的 Lint/Build 基建任务（B-6 → T86）

| 交付物 | 说明 |
|---|---|
| ESLint + Prettier 配置 | 先确认依赖是否已存在，**禁止擅自引入未评估的第三方库** |
| 根 `lint` / `lint:fix` / `build` 脚本 | `build` 须验证 core→backend→frontend 三段顺序依赖 |
| CI Stage 2 | `npm run lint` + 三 workspace 的 `tsc --noEmit` |
| 存量违规分级 | 先以 `warn` 全量盘点，**只对新增代码强制 `error`**，存量登记逐步收敛 |

**必做验收**：故意写一个 `any` + 一处格式错误 → lint **必须非 0**，
证明规则真生效而非空跑（G2.2）。

> **T66（`any` 清零）与 E6（无死代码）的前置就是 T86。**

### 3. 新增 §12.7 Wave 出口门槛 —— 逐波止损（硬阻断）

**问题**：原计划只在 T78 做**一次性**全局判定。而 Wave 1 全是**静默污染类**错误
（T84 超卖 / T87 去重语义 / C4-C5 / 插件计时），这类错误一旦漏过，
后续 6 波算出的持仓成本、收益率、复盘胜率**全部错位且不报错**，到 T78 才发现已无干净切分点。

**解法**：8 个 Wave 出口门槛 G1-G8，把 §12 的一部分验收**前移**到每波结束处。

| 规则 | 内容 |
|---|---|
| 判定 | 只有 **PASS / FAIL**，**无 COND**（COND 会让硬阻断形同虚设）|
| 落档 | `docs/audit/wave-N-gate.md`，含逐条 PASS/FAIL/豁免 + **实测原始数据** + 本波 commit 区间 |
| 阻断 | 任一 FAIL → **本波全部 commit 一律不合入 `main`** |
| 不可豁免 | **数据正确性类门槛永久不可豁免**（标 🔒） |
| 豁免条件 | 须写明理由 + 指向 §9.3/§13 条目；**同一门槛最多豁免 1 个 Wave**，连续 2 波自动升级为阻塞项 |

**G1 是最严的**（6 条 🔒）：三项数据正确性断言、`runAllChecks()` 返回 12 条、
`{total:2, success:2, timeout:0}`、全库无负持仓/负成本/同时刻重复等。

**回滚可行性依赖 commit 粒度**：因规定「每个 T 任务一条 commit」，一波内 commit 区间可整体
`git revert` 而不留半拉子改动 —— **这是 Gate 流程成立的前提，不可把多个任务合并成一条 commit。**

> **T78 不是首次验收，是最终验收。** §12.6 的全局 PASS 前提是 G1-G8 全 PASS。

## 后果

### 正面
- 静默污染类错误在 Wave 1 结束即被拦截，而非拖到 T78
- 「Lint 失败阻断合入」从 SDD 空文变成可执行任务
- 覆盖率暂缓有明确的恢复义务与时点，不会永久搁置

### 负面 / 代价
- 每波增加 <0.5d 的 gate 执行成本
- 新增 `tests/http/` 会引入端口依赖，**必须同步执行 AGENTS.md 的收尾四步**
- 覆盖率冻结期间，对算法改动的回归保护弱于 SDD 目标

### 对真相源的影响
- ✅ **SDD §12.2 已加暂缓标注 + T86b 恢复义务**
- ✅ **AGENTS.md 已加「Wave Gate（硬阻断）」一节**
- ⏳ 待回写：`docs/coding-standards.md:135-150` 的「机器强制执行」章节 ——
  其声称 `eslint.config.js` / `.prettierrc` / 覆盖率 Gate 存在，**但三者均不存在**

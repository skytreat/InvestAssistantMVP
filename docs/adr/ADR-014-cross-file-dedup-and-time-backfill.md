# ADR-014 —— 跨文件去重与成交时间回填方案

## 背景

同一券商的「成交流水」与「交割单」是两个文件，内容**高度重叠**：

```
国泰 ETF：成交 125 行 / 交割 134 行
  交割行按 (标的+日期+方向+价+量) 匹配成交行：125 / 134   ← 全命中
  成交独有（交割无对应）：0 行
  交割独有 9 行 = 全部非成交事件（货币ETF申赎杂项 4 + 基金现金分红 5）
国泰股票：成交 12 / 交割 14 → 12/12 全匹配，交割独有 2 行 = 红利入账
```

两个关键事实：

1. **交割单没有成交时间**（只有交收日期），成交流水有（精确到百分秒）
2. **「同日同码同方向多行」有两种截然不同的含义**：
   - 同一笔交易的**两份冗余导出**（价量全同）→ 只能留一条
   - **真实的分笔成交**（价或量不同）→ 必须全留
     （实测：某标的同日连续 5 笔卖出，价 33.580/33.580/33.570/33.560/33.460）

若不处理，全量导入后**每笔交易被算两次 → 持仓与盈亏翻倍**。

## 决策

### 1. 跨文件去重

**去重键** = 标的 + 日期 + 方向 + 价格 + 数量

| 键相同 | 价与量 | 处置 |
|---|---|---|
| 同 | **同** | 同一笔的冗余导出 → **只留一条**，记录另一来源文件 |
| 同 | **不同** | 真实分笔 → **全部保留**，按出现顺序编号 |

**标的名称不得用作键**（实测同一标的存在多个名称变体）。

### 2. 成交时间回填

以**交割单为骨架**（它含资金发生数、资金余额、10 项费用明细、证券余额，信息更全），
成交流水仅用于**补充成交时间**。

**匹配优先级（降级）**：

| 级别 | 键 |
|---|---|
| L1 | 稳定标识（合同序号 / 成交编号） |
| L2 | 内容键（标的+方向+价格+数量）+ 日期窗口（默认 ±2 天，可配置） |
| L3 | 内容键 + 出现顺序配对 |

**日期权威源 = 成交流水的日期**（按定义即成交日）；交割单的日期**只作辅助键**。

**低置信度匹配（L2/L3）必须单列统计。**

### 3. 行级幂等

**成交编号不可靠**（实测三种形态：科学计数法丢精度 / 数字与文本混排 / 同一编号被两行共用）。
故幂等键 = `row_hash`（归一化内容 SHA-256）**+** `content_seq`（同哈希内容在批次内的出现序号）。

→ 同内容多笔**不被误判为重复**，同一文件重复上传**被识别为重复**。

## 后果

### 正面

- 导入不翻倍（否则整个对账失去意义）
- 真实分笔成交完整保留（否则持仓数量错）
- 交割单与成交流水**两份信息合并到一行**：既有成交时间，又有费用明细与资金流

### 负面 / 代价

- 跨文件去重**必须先于**补录，否则错误会被固化到业务层
- 日期口径**必须按券商实测确认**（实测某券商的「交收日期」= 成交日，含跨境 ETF，
  但这是该券商该文件的实际口径，**不是通用规律**）
- `contractNo` 只有部分券商有（国泰有「合同序号」，华宝无）→ 降级路径必须能走通

## 被否决的备选方案

| 备选 | 否决理由 |
|---|---|
| **按文件分别导入，不做跨文件去重** | 持仓与盈亏翻倍 |
| **用成交编号做唯一键** | 三种不可靠形态（SDD §2.9.2） |
| **用「标的+日期」做去重键** | 真实的同日多笔会被误吞（实测同日 5 笔） |
| **以成交流水为骨架** | 丢失费用明细与资金流 → 资金校验与差额归因都做不了 |
| **假定交割日期 = 成交日** | 该结论只对实测的券商/文件成立，非通用规律 |

## 关联证据

- 实测 6 份文件（1627 行）两两组合，回填命中 **125/125** 与 **12/12**，成交独有 0 行
- 真实分笔成交实证：某标的同日 5 笔，价 33.580/33.580/33.570/33.560/33.460
- 成交编号三种不可靠形态的实测样例见 `InvestAssistantV3_NewRequirements.md` 附录 C

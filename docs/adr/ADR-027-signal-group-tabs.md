## 1. 背景

信号页（`/signals`）现状：全量信号按日期分页 + 强/中/弱/已过期筛选 + 今日 Top5。
两个问题：

1. **「我关心的持仓」与「我观察的自选」混在一个列表**：用户看完某只持仓的最新信号后，
   无法按「组」快速回答「我持仓的每只标的今天有什么结论」；
2. **组合信号与单条件信号地位平铺**：owner 已拍板组合合成口径（D1 AND / D2 min / D3 预生成 / D4 历史不可变，
   `proposal-combined-strategy.md` §6），组合信号以 `plugin_id='combo:<id>'` 落库。
   展示层需要回答「这只标的综合起来是买、是卖、还是持有不动」——但**合成结论只能来自组合**，
   不能由前端把单条件信号投票合成（会制造第二套判据，违背 D3「判据只有一份」）。

## 2. 决策

### 2.1 页面结构：信号页两 Tab（默认「持仓组」）

| Tab | 口径 | 说明 |
|---|---|---|
| **持仓组** | `calcAllPositions(userId)` 净持仓 > 0（ADR-021 同源，与 `/api/positions` 一致） | 默认 Tab |
| **自选组** | `user_asset_rel`（`rel_type='watch'`、`is_deleted=0`）**且不在持仓组** | 避免双 Tab 重复展示 |

- 组内按**标的**轻量聚合：**分组头**（一行，`<th colSpan scope="rowgroup">`，每标的一个 `<tbody>`），
  组头**不带市值/盈亏**（那是持仓页职责，信号页只回答「信号结论」）；
  组内排序：**组合行（`combo:<id>`）置顶**，其余单信号按 `strength` 降序（`NULL` 垫底）。
- 组头可标注**「现金类」**（`asset_class='cash'`，以 `asset_class` 表为准；PR-1/ADR-024 回填后自动生效）。
- **今日 Top5 卡保持全局不动**（INV-S3-25 语义是全局摘要，不按组拆分）。
- **已清仓标的的历史信号：两 Tab 都不显示**（组只回答「当前该关注什么」；历史信号仍在「全部」筛选下可查）——登记为 plan_v2 **I-42**（遗留待确认是否加「已清仓」组）。

### 2.2 综合结论：组合优先，不合成

| 口径 | 规则 |
|---|---|
| **唯一来源** | 只取该标的当日的 `plugin_id='combo:<id>'` 行 ⇒ 显示其方向/强度为「综合结论」；**无任何组合信号 ⇒ 显示「无组合结论」**（不合成、不投票、不做前端 min/AND 推导） |
| 细则① | **无信号 ≠ 持有**：某标的当日没有信号，组头只标「无当日信号」，不解读为「继续持有」 |
| 细则② | **HOLD 不计票**：风险 HOLD（`sub_category='risk'`、`strength=NULL`）不参与综合结论 |
| 细则③ | **冷却/过期置灰**：处于 F6 冷却合并或已过期的信号**置灰展示、不参与综合结论**（与 F6「展示层合并」口径一致） |
| 细则④ | **已采纳/忽略仍参与**：`adopted`/`ignored` 标记的状态列照常显示（INV-S3-27），不影响结论本身 |
| 细则⑤ | **指定交易日/非交易日**：选中的日期无该标的信号 ⇒ 组头显示「无当日评估」（区分「没跑信号」与「跑了没命中」：后者看 system_log，页面不展示） |
| 细则⑦ | **买卖冲突 ⇒ 卖出优先**：同一标的同时存在 buy/sell 方向信号时，综合结论取 **sell**（安全侧） |

### 2.3 后端契约（T154）

- `GET /api/signal` 新增可选参数 `scope=holdings|watch`（缺省 = 现状全量，**向后兼容**）：
  服务端按上表口径算出该组标的集合（`scope=holdings` 走 `calcAllPositions`；`scope=watch` 走 `user_asset_rel` 并排除持仓组），
  在 WHERE 追加 `asset_code IN (...)`（**1 次 IN**，遵守 SDD §5.3 批量约束）；
- 响应每行新增 `scope`（该标的当前归属：`holdings` / `watch`；不在两组为 null）与 `is_cash`（`asset_class='cash'`）字段，
  前端据此画组头与现金类标注；
- 组头数据（标的名/净持仓/现金类）**由前端用既有接口组装**（`/api/positions` + `/api/signal` 的 `is_cash`），不新增聚合端点（MVP 控制面）。

### 2.4 单独立项：组合未命中不落库（T155）

现状：组合求值未命中（SKIP/NO_SIGNAL/条件失败）时**不写 `user_strategy_signal`**，只写 `system_log`。
⇒ 「无组合结论」无法区分「跑了组合没命中」与「当天没跑组合」。细则⑤先按**页面只说「无当日评估」**处理，
T155 再决策是否给 `system_log`/响应加「已评估未命中」标记（需 owner 裁决是否把 NO_SIGNAL 落 `user_strategy_signal`
——默认**不落**，保持「信号表只存成立信号」的既有语义）。

## 3. 后果

**正面**

- 信号页从「全量流水」升级为「按关注对象分组的结论视图」，回答「我今天要管什么」；
- 综合结论唯一来源 = 组合（判据只有一份，D3），前端零合成逻辑；
- 持仓组口径与 ADR-021 同源（`calcAllPositions`），无第二套持仓推导。

**负面 / 代价**

- `scope=holdings` 每次请求算一次 `calcAllPositions`（ADR-021 实测 8ms，可忽略）；
- 自选组排除持仓组 ⇒ 同一标的清仓后**自动从自选组出现**（watch 关系仍在）——属预期（自选本就是「观察」）；
- 组头不带市值/盈亏，用户若要同时看金额仍需去持仓页（明确不做跨页合并）。

## 4. 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 前端对单条件信号投票合成综合结论（AND/min 在浏览器里算一遍） | 第二套判据，违背 D3；与后端 comboEvaluator 可能漂移；owner 拍板「不合成」 |
| 新增 `/api/signal/group` 聚合端点（服务端算组头） | MVP 控制面：组头 = 标的名 + 净持仓 + 现金类，既有接口可组装；聚合端点等真实需要（如组头带盈亏）再评估 |
| 三 Tab（持仓/自选/已清仓） | 已清仓历史信号「两 Tab 不显」已够 MVP；「已清仓」组登记为 I-42 遗留，不预设 |
| 综合结论允许风险 HOLD 参与 | HOLD 无 `strength`、不进 F1（既有口径）；把「风险提示」当「卖出结论」语义错位 |
| 组合未命中也落 `user_strategy_signal` | 信号表只存成立信号（唯一键/去重/Top5 全按此设计）；「未命中」是过程信息，属 system_log；T155 再裁决 |

## 5. 验证

- 后端单测：`scope=holdings`（净持仓 >0 集合）/ `scope=watch`（watch 且非持仓）/ 缺省不变；`is_cash` 来自 `asset_class`；IN 查询 1 次；
- 前端单测：两 Tab 默认持仓组；组头 rowgroup 结构（`<th colSpan scope="rowgroup">` + 每标的 `<tbody>`）；
  组合行置顶 + strength 降序；无组合 ⇒「无组合结论」；买卖冲突 ⇒ 卖优先展示；冷却/过期置灰；Top5 全局不随 Tab 变；
- 双端一致性：组口径（calcAllPositions / user_asset_rel）与 `/api/positions`、`/api/signals` 现有断言同锚点。

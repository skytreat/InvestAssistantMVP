# ADR-023 —— C8「行情更新执行时长」阈值 120s → 1200s（按生产实测放宽）

| 项 | 值 |
|---|---|
| **状态** | ✅ 已接受（2026-11-13，owner 裁决「放宽阈值」） |
| **落地** | 本次修复（`validator.ts` 的 `TOLERANCES` + Requirements §7.1 + SDD §5.7 / §12.5 PE4 + 2 处测试断言） |
| **关联偏差** | §13.2 **I-40**（新增） |
| **关联文档** | Requirements §7.1（C8 行）、SDD §5.7 C8、SDD §12.5 PE4 |
| **不取代** | 不取代 ADR-018（校验补跑）、ADR-021（信号域来源） |

---

## 1. 背景（生产实测，非估计）

### 1.1 现象

生产 2026-11-12 的 17:01 校验段（`system_log.log_type='datacheck'`）：

```
5042 | WARN | C8 WARN | 行情更新耗时 571s（上限 120s，日志时间 2026-11-12 09:09:39）
5048 | WARN | C1-C12 校验完成: ERROR=0 WARN=1 TOTAL=12 补跑=跳过（增量语义）
```

⇒ **每天固定一个 C8 WARN**。

### 1.2 实测：全市场日线更新要 571s

| 项 | 实测值 |
|---|---|
| tdx2db oneshot 起止 | 17:00:07 → 17:09:38（UTC 09:00:07 → 09:09:38）= **571s** |
| systemd 约束 | `deploy/tdx2db.service` → `TimeoutStartSec=1800`（30 分钟） |
| 写入内容 | 全市场日线（`raw_kline_daily` 约 2980 万行）+ 复权因子 + 除权表 |

⇒ 120s 这个阈值与"全市场日线更新"这个实际工作量**差 4.8 倍**，不是偶发。

### 1.3 为什么不能"忽略这条 WARN"

C8 是 **Requirements §7.1 的硬口径**（PRD §6.4 引用），失败级别 WARN。
⇒ 每天一条 WARN ⇒ ① 日志噪音；② **真异常被淹没**（将来某天 1200s 以上，仍然只是同一条 WARN）；
③ 阈值本身与现实不符 ⇒ 属于**规则问题**，不是"实现没达标"。

### 1.4 连带事实（不是阈值造成的，但相关）

tdx2db 占写窗口 571s ⇒ Node 侧 17:01 校验**必须等写窗口结束**才跑（实测 09:09:38 结束 → 09:09:41 校验开始），
⇒ 整条盘后链路后移 ~10 分钟：校验 09:09:41 → 信号 09:10:44 → 除权 09:10:45 → 纸面 → 备份 09:10:50。
这是 **写窗口协议（ADR-012）的正常行为**，与阈值取值无关。

## 2. 决策

C8 阈值：**120s → 1200s（20 分钟）**。

取值依据：

- ≈ 生产实测（571s）的 **2.1 倍**，给慢日/网络抖动留余量；
- **早于** systemd `TimeoutStartSec=1800` ⇒ 真正超时（>30 分钟）时 unit 会被直接杀掉，
  那时 C8 反而写不出日志 ⇒ 阈值必须留出这 10 分钟差，否则 C8 与 systemd 互相掩盖；
- 保持 WARN 级与 Requirements §7.1 的失败级别不变（只改阈值，不改语义）。

## 3. 后果

**正面**

- 消除每日必 WARN，C8 恢复"真异常才告警"的语义；
- Requirements / SDD / PE4 / 代码四处口径同步，不再有"文档说 120s、现实 571s"的长期偏差。

**负面 / 代价**

- 阈值是**守卫**不是目标：真正的优化方向是把 tdx2db 的全市场日线抓取提速（当前 571s）—— **未做**，属独立课题；
- 盘后链路整体后移 ~10 分钟的事实**不变**（根因是 tdx2db 耗时，不是阈值）。

## 4. 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| 保持 120s | 每天必 WARN ⇒ 噪音 + 真异常被淹没；且它是 Requirements 硬口径，不能靠"忽略"消解 |
| 优化 tdx2db 到 120s 内 | tdx2db 是**外部 Go 二进制**，仓库无源码；10 倍提速不现实（应作为独立课题） |
| 把 C8 降级为 INFO 或取消 | 削弱"行情更新超时"的可观测性；真正超时（>30 分钟）由 systemd 杀进程，此时 C8 已写不出日志 |
| 阈值取 1800s（= systemd timeout） | 等于取消 C8（超 30 分钟时 unit 已被杀 ⇒ 日志写不出来）⇒ 选 1200s 保留"提前 10 分钟告警"的余量 |

## 5. 验证

- **生产**：2026-11-12 实测 571s ≤ 1200s ⇒ C8 应判 PASS（次日晚间 17:01 可在 `system_log` 观测）；
- **测试**：`apps/backend/tests/unit/t85-c1-c12-semantics.test.ts` 与 `validator.test.ts`
  断言 `TOLERANCES.MAX_UPDATE_SECONDS === 1200`；
- **文档**：Requirements §7.1（C8 行）、SDD §5.7 C8、SDD §12.5 PE4、plan §13.2 I-40 同步。

## 6. 后续（不在本次范围）

1. **tdx2db 全市场日线更新提速**（独立课题）—— 在此之前，盘后链路整体后移 ~10 分钟属既定行为；
2. 若某日 C8 仍 WARN ⇒ 说明当日超过 20 分钟，属**真异常**，按 C8 流程排查。

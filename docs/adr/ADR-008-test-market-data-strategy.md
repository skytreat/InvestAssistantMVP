## 1. 背景（实测数据，非估计）

2026-10-20 为加速 Wave 5 ~ Wave 8 的开发循环，对后端测试套件做了逐文件计时：

```
断言累计 200.1s（墙钟 ~240s）· 54 个测试文件
  unit         42 文件  77.6s (39%)
  smoke         4 文件  76.9s (38%)
  integration   8 文件  45.7s (23%)
→ 11 个文件占了 89%
```

**慢的根因不是测试框架，是真实行情库的全表物化**：

| 慢项 | 耗时 | 根因 |
|---|---|---|
| `smoke-m3`「SQLite 热备份」 | **36.1s** | `backupDuckDB()` 执行 `COPY v_stock_qfq TO parquet` —— 把 **1.24GB / 2800 万行**的实时计算视图物化并导出 |
| `smoke-m1`「/api/market/latest」 | **16.1s** | `SELECT … FROM v_stock_qfq ORDER BY date DESC LIMIT 5` —— 为拿 **5 行**物化全表（4 个 JOIN）|
| `watchPromote` | 10.3s | 多标的查询打视图 |
| `t50` / `quoteRerun` / `t55` | 6.0 / 6.0 / 5.2s | 同类 |

**根本原因**：`v_stock_qfq` 等 6 个视图是**实时计算视图**（不存储），定义形如

```sql
CREATE VIEW v_stock_qfq AS
WITH latest_factors AS (SELECT symbol, argmax(hfq_factor, date) AS latest_hfq
                         FROM raw_adjust_factor GROUP BY symbol)
SELECT … FROM raw_kline_daily s
  INNER JOIN raw_symbol_class sc ON (s.symbol = sc.symbol AND sc."class" = 'stock')
  LEFT  JOIN raw_adjust_factor f  ON (s.symbol = f.symbol AND s.date = f.date)
  LEFT  JOIN latest_factors lf    ON (s.symbol = lf.symbol)
  LEFT  JOIN raw_basic_daily b    ON (s.symbol = b.symbol AND s.date = b.date);
```

基表 `raw_kline_daily` 实测 **2800 万行 / 1.25 万只**（stock 1841万 / block 363万 / etf 310万 / index 303万 / unknown 95万 / bstock 71万）。

**下推行为实测**（决定「什么时候能用视图」的判据）：

| 查询形态 | 实测 | 能否下推 |
|---|---|---|
| 视图 + **单标的** `symbol = ?` | **0.05s** | ✅ 等值下推生效 |
| 视图 + **IN(多只)** | **2.75s** | ❌ 物化全表再过滤 |
| 视图 + **全市场无谓词** | **12.18s** | ❌ |
| 基表 + IN(多只) + 窗口函数 | **0.08s** | ✅（**41x**）|
| 基表 + 全市场 + 日期过滤 | **0.16s** | ✅（**76x**）|

⇒ **视图的物化成本是 O(全表)。只有当「真正需要的行集」≈ 全表时，用视图才划算。**

## 2. 决策

### 2.1 建立「迷你 DuckDB」作为测试行情库

| 项 | 值 | 依据 |
|---|---|---|
| **标的数 N** | **250（总量）** | 66 个被测试直接引用的标的（`sh600000`/`sh600001`/`sz000001`/`sz300750`…）+ 按真库真实 class 比例补足 |
| **class 比例** | stock 49.5% / etf 22.8% / unknown 10.9% / block 9.1% / index 6.4% / bstock 1.3% | 真库 `raw_symbol_class` 实测分布（**不手工配额**）|
| **抽样确定性** | `hash(symbol)` 排序取前 k（**非随机**）| 可复现，无需固定 seed |
| **跨度 days** | **365 自然日**（242 交易日）| ⚠️ **半年不够**：`packages/core/tests/fixtures/golden/{kdj,macd,rsi}.json` 全部是 **221 根**（`meta.source` 写明 `ORDER BY date DESC LIMIT 221`，跨度 335 自然日）；半年只有 **119 个交易日** ⇒ golden 断言取不到数据 |
| **视图** | 6 个视图**必须重建**，定义从真库 `duckdb_views()` **导出** | 视图不存储；且 `v_stock_qfq` 是 `round(…,2)` 而 **`v_etf_qfq` 是 `round(…,3)`**（`v_stock_hfq`=2 / `v_etf_hfq`=3；**bfq 视图不取整**）⇒ 手抄必错 |
| **入库形态** | **Parquet + 生成脚本**（不是 DuckDB 二进制直接进 git）| 二进制 15MB 每次重生成都是不可读的 git diff；Parquet 可读可 diff，与 `packages/core/tests/fixtures/golden/` 的先例一致 |
| **实测体积** | ≈ **15MB**（vs 真库 1.24GB）| 见 §5 曲线 |

**天数几乎免费**（体积被固定开销主导，不是 K 线行数）：

| N=250 | 体积 | K线行数 | view 查询 |
|---|---|---|---|
| 180d（半年）| 14.3MB | 27,655 | 74ms |
| 250d | 14.0MB | 36,320 | 104ms |
| **335d**（golden 跨度）| 14.8MB | 47,703 | 73ms |
| **365d（采用）** | **14.8MB** | 50,649 | 108ms |

⇒ 「半年 vs 一年」是**伪问题**，直接给一年。

**N 是体积的主要杠杆**：120→8.8MB / 250→14.8MB / 500→24.5MB。

### 2.2 三档切换（显式，不靠约定）

| 档 | `DUCKDB_PATH` | 何时 | 行情用例 |
|---|---|---|---|
| **dev（默认）** | 迷你库 | 日常开发 | 跑 |
| **CI** | 现生成迷你库 | 每次 CI | 跑 |
| **full（显式）** | 1.24GB 真库 | 门禁前 / 性能基准 / 发布前 | 跑（含 `scan_5000_target`）|

### 2.3 两层开关（拆分「数值可信」与「规模真实」）

**现状问题**：`MARKET_DATA_AVAILABLE` 是**一个开关管所有行情用例**，把两类混在一起 ⇒ CI 上要么全 skip、要么全跑但没数据。

| 层 | 语义 | 迷你库上 | 用例类型 |
|---|---|---|---|
| **数值型** | 数值与真库一致（迷你库是真库切片）| ✅ **跑** | `sh600000` 基准价 == 最新前复权收盘价；KDJ/RSI/MACD 与 golden 逐位相等 |
| **规模型 / 性能型** | 规模与耗时必须真实 | ❌ **必须真库** | 候选池 > 3000；`scan_5000_target` ≤ 3s；PE1-PE6 |

⇒ **两个独立开关**，不再混用。

### 2.4 视图使用约束（技术契约，非「建议」）

> 视图仅在「需要全量行集」时使用（一次性导出 / 全量统计）；
> **「取最近 N 根」且标的数 > 1 → 走基表 + `IN` 下推 + 手工复权因子**；
> **单标的历史序列 → 走视图无妨**（等值下推，0.05s）。

⚠️ **改写必须与视图逐位等价**（`round` 位数、`COALESCE(…,1)` 缺省、`bfq` 不取整、`raw` 不套因子、`class` 过滤语义）。

## 3. 代价（明确接受）

| 代价 | 说明 | 缓解 |
|---|---|---|
| **数值可信度需分层** | 迷你库数值可信、规模不可信 | 两层开关（§2.3）把两类用例分开 |
| **迷你库会过期** | 真库每日 17:00 更新 | 固定快照 + 一键重生成脚本；数值稳定优先于新鲜 |
| **多一份数据制品** | Parquet 入库 + 生成脚本 | 与 `golden/` 同一性质，可审计 |
| **PE4/PE2 仍需真库** | 性能门槛必须在真实规模上量 | full 档显式触发 |
| **新增一处「假绿」风险** | 迷你库上跑通 ≠ 真库上跑通 | 门禁前跑 full 档 + CI 跑迷你档，两者互补 |

## 4. 备选方案与否决理由

| 备选 | 否决理由 |
|---|---|
| **CI 现生成合成数据**（无真库时造伪随机数据）| ❌ **合成数据的数值与真库不同** ⇒ 依赖精确数值的断言在 CI 上必然不一致 ⇒ 只是把「skip」换成「可能假绿」|
| **CI 直接用 1.24GB 真库** | ❌ 下载慢、仓库不是行情数据的权威源、体积不适合 CI |
| **不做迷你库，只修查询反模式** | ⚠️ 反模式修复是**必要但不充分**：它让**真库**上的查询变快，但**不解决 CI 无行情数据 ⇒ 31 个用例长期 skip** 的盲区 |
| **只做迷你库，不修反模式** | ❌ **迷你库会掩盖真实性能缺陷** —— `/api/market/latest` 真库 12.18s（且**免鉴权** ⇒ 可被反复调用烧 CPU）在迷你库上只要 0.3s，开发期完全看不出来 ⇒ **两者互补，不是替代** |
| **把迷你库二进制直接进 git** | ❌ 15MB 不可读二进制 diff；改用 Parquet + 脚本 |
| **只保留单一 `MARKET_DATA_AVAILABLE` 开关** | ❌ 数值型与规模型用例的可跑性不同 ⇒ 必须拆成两层 |
| **N 取 3000+** | ❌ 体积 135MB；N=250 已达 113x 提速，**边际收益递减** |

## 5. 规模-成本曲线（实测，2026-10-20）

```
真库对照: 1.24GB | raw_kline_daily 2800万行 | view 查询 12180ms

     N   days      生成      体积    K线行数   view查询  batch查询
   100   250d    1928ms    8.0MB      15259      71ms      57ms
   300   250d    2330ms   16.5MB      43450     143ms     110ms
  1000   250d    3308ms   46.3MB     139458     266ms     244ms
  3000   250d    6805ms  135.0MB     421738     804ms     706ms
 12449   250d   24804ms  555.3MB    1755170    3054ms    2516ms   ← 全部标的
  3000    60d    6444ms  129.8MB     136997     759ms     670ms
 12449    60d   23575ms  526.3MB     569047    2708ms    2539ms
```

**采用规格：N=250 / days=365** ⇒ 14.8MB · view 查询 108ms（真库 12180ms ⇒ **113x**）。

## 6. 与既有决策的关系

- **不违反 ADR-001**（测试框架版本）：本 ADR 只决定**测试数据形态**，不改测试框架
- **强化 ADR-006**（工程门槛与验收分层）：G2.4 / G5.x 等覆盖率门槛此前在 CI 上有「行情用例 skip ⇒ 覆盖率被低估」的系统性偏差，本 ADR 关闭该盲区
- **不改变 L1 业务规则**：不涉及任何业务口径
- **实施计划的关系**：plan 记「做什么」（T60b / T60 剩余项 / 视图物化修复任务卡），本 ADR 记「为什么」；**plan 不复述本 ADR 的规格**（规格落在 SDD）

# ADR-009 —— 券商流水事实层与业务记录层的分离

> **状态**：已接受
> **日期**：2026-10-20
> **决策者**：owner
> **关联**：Requirements §2.4.3 / §2.6.3 / SDD_v3 §4 / §5 / §9.1-9.3 / plan T103-T110

---

## 背景

V3 要导入券商成交与交割单，做对账与补录。实测发现三个绕不开的事实：

1. **同一券商的「成交流水」与「交割单」是子集+增量关系**（交割单 = 成交流水 ∪ 非成交事件）。
   实测：成交 125 行**全部**匹配到交割单（匹配率 100%），交割独有 9 行全为非成交事件。
2. **同一笔交易会出现在多个文件里**（内容完全相同）→ 不跨文件去重则**持仓与盈亏翻倍**。
3. **不是所有事件都该成为「交易」**：
   - 场外基金申赎 —— 场外净值与场内价格不同源，成本口径无法与行情层对齐
   - 现金分红 / 送股 / 特殊调账 —— 影响资产但不产生买卖
   - 逆回购 / 货币 ETF —— 是**现金类资产**，需要参与收益，但不应按风险资产口径计算

若把「导入」当成一个开关（导 / 不导），就会出现两种坏结果：
要么全部导入 → 交易记录被场外、占位、逆回购污染；要么全部不导 → **现金类收益整体漏掉**
（实测逆回购半年利息 7,501 元，占风险资产净流出的 29%），系统显示的账户收益率会与券商口径**差 1 个百分点以上**。

## 决策

**拆开「导入」这个开关，改为三个正交维度**：

| 维度 | 含义 | 逆向回购 / 货币 ETF |
|---|---|---|
| ① 进系统记录（作为交易） | 进 `user_trade_record`，有成本价、影响持仓 | ✅ 作为**现金类资产** |
| ② 进事实层（可对账 / 可归因） | 进 `broker_trade_record`，保留原始证据 | ✅ |
| ③ 参与收益计算 | 影响收益率 | ✅ |

**场外基金 / 占位事件**：① ❌ ② ✅ ③ ❌ —— 保留在事实层只是为了**差额归因**，
否则对账报告只能报一个「对不上」，用户无从下手。

**不引入账户类型分支**：owner 已确认全部账户为普通账户，故「融券 / 融券购回」**确定映射为 `REPO`**。

## 后果

### 正面

- 对账报告能给出**差额归因**（逆回购 X + 货币 ETF Y + 分红 Z + 未覆盖期间 W + 口径差异 V + **真实差异 U**），
  残差单独置顶，**不用「其他」兜底**
- 系统总收益率可与券商口径对齐，同时分项（风险 / 现金 / 费用）可见
- 解析缺陷可据 `raw_row_json` 重放，无需用户重新上传文件

### 负面 / 代价

- 事实层与业务层**双写**（补录时两边都有），撤销逻辑必须严格区分两层
- 现金类资产需要**独立的资产分类**（`asset_class` 表）—— 现有 `raw_symbol_class`
  只有 `stock/etf/index/bond/unknown/block/bstock`，**分不出货币 ETF 与股票 ETF**
- 多一套分类维护成本（规则初判 + 人工修正 + 历史重算）

## 被否决的备选方案

| 备选 | 否决理由 |
|---|---|
| **全部不导**（MVP 现状） | 现金类收益整体漏掉，收益率与券商口径差 1 个百分点以上 → 用户会认为系统算错 |
| **全部导入 `user_trade_record`** | 场外、占位、逆回购污染交易记录；且需要**扩展 `trade_type` 枚举**（→ 第三次表重建） |
| **只做「对账」不落事实层** | 差额无法归因；解析缺陷无法重放 |
| **用「标的代码 + 名称」做去重键** | 实测同一标的存在多个名称变体（`159530 机器人ETF易方达` / `159530 机器人E`） |
| **引入账户类型维度** | owner 账户全为普通账户，当前不需要；将来接信用账户时再引入（SDD §4.2.1 已留警示） |

## 关联证据

- 实测 6 份券商文件（1627 行）、40 种交易类别、83 个标的
- 逆回购：180 对 1 天期，利息 **7,501.46 元**，在途本金日均 86.8 万，年化约 2.04%
- 跨文件回填命中率 **125/125**（国泰 ETF）、**12/12**（国泰股票）
- 行内资金自洽 **145/148**（3 行为现金分红，公式不适用）

# ADR-003：交易记录去重语义 —— 追加而非拒绝

| 项 | 值 |
|---|---|
| **状态** | ✅ 已接受（Accepted） |
| **日期** | 2026-10-17 |
| **裁决人** | 项目所有者 |
| **关联** | 实施计划 §13.1 **B-11**、§13.4 |
| **落地任务** | T87（**须先于 T49 或同期**）、T84 |
| **真相源依据** | SDD §12.3 B4：「同一日内同一 symbol 多次买入（幂等）→ **不触发 UNIQUE 冲突，正常追加**」 |

---

## 背景

代码 `configStore.ts:25-47` 的 `user_trade_record` 有约束：

```sql
UNIQUE(user_id, asset_code, trade_type, trade_date)
```

后果：**用户一天内分两笔买同一标的，第二笔直接 409 `TRADE_DUPLICATE`** ——
这与 SDD §12.3 B4 明写的「正常追加」直接矛盾，是真实的产品缺陷。

初版实施计划在发现此矛盾后登记为待裁决。裁决过程分两轮：

1. 第一轮裁决：**追加**，且**成交时间与标的代码、交易份额共同构成主键**
2. 第二轮修订：**成交时间进主键，份额不进**

## 决策

### 唯一键

```sql
UNIQUE(user_id, asset_code, trade_type, trade_date, trade_time)
```

### 新增列

```sql
trade_time TEXT NOT NULL   -- 秒级 HH:mm:ss，必填无默认
```

### 字段语义

| 项 | 决定 | 理由 |
|---|---|---|
| 「同日分笔」如何区分 | **靠 `trade_time` 区分** | 裁决明确「份额不进主键」 |
| `trade_time` 是否必填 | **必填，无默认值** | 见下方「结构性后果」 |
| 时间精度 | **秒级**（前端 `<input type="time" step="1">`） | 分钟级会让同一天同一标的同一类型只能有一笔 |
| 留空是否允许 | **不允许** | 留空落 `00:00:00` 会退化成原约束 |

## 结构性后果（裁决的直接代价，必须知晓）

把份额移出主键后，**唯一能区分「同日同标的同类型多笔」的字段只剩 `trade_time`**。
由此产生两个必然结果：

### 1. `trade_time` 必须必填

若允许留空（落 `00:00:00`），则同一天同一标的同一类型**仍然只能录一笔** ——
**与「追加」裁决直接矛盾**。故改为 `NOT NULL` 且无默认值。

### 2. 粒度从「天」细化到「秒」

**同一标的同一天同一类型只能有一笔。** 补录历史交易时，用户若对多笔填了相同时间
（如都填 `09:30` 来表达「同一天买」），第二笔会 409。

**缓解措施（必做）**：前端**提交前预检**当日该标的该类型已占用的时间集合，
命中则**禁用提交并提示「该时刻已被占用，请修改成交时间」** ——
不能让用户提交后才吃错误码。

## 连带影响

| 项 | 影响 |
|---|---|
| 旧数据迁移 | 无 `trade_time` 的记录按 `created_at` 的时分秒回填，避免违反新 UNIQUE |
| 持仓回放排序 | T84 的时点校验排序由 `trade_date ASC, id ASC` 改为 **`trade_date ASC, trade_time ASC, id ASC`** |
| DDL 变更方式 | 改 UNIQUE 必须**幂等表重建**（`CREATE TABLE IF NOT EXISTS` 对已存在的表无效）。**T49 改 CHECK + T87 改 UNIQUE 合并为一次重建**，不叠加 |
| 错误码 | 新增 `TRADE_DUPLICATE`（SDD §4.3 原表 10 码不含它），文案改为「该标的在该时刻已有同类型交易」 |
| 回滚测试用例 | 同日同标的同类型、**同时间不同份额 → 仍 409**（反向断言，验证份额确实不在主键内） |

## 后果

### 正面
- SDD §12.3 B4 的「正常追加」落地，用户可分笔买入
- 去重语义从「按天」精确到「按秒」，误判概率大幅降低

### 负面 / 代价
- **成交时间变必填**，补录历史时用户需提供（通常不精确知道的）时刻
- 同一天同一标的同一类型只能有一笔，需靠前端预检引导
- 迁移脚本需按 `created_at` 回填

### 对真相源的影响
- ✅ **SDD §3.2 DDL 已回写**（含 `trade_time`、新 UNIQUE、为何必填、DDL 变更判据）
- ✅ **SDD §4.3 已补 `TRADE_DUPLICATE`**
